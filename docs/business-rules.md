# 业务口径基线（用户设定，长期有效）

> **本文是什么**：`dsh-media-plugins` 的**业务行为口径**唯一真源——"工具怎么用"之外，"产出应该长什么样、什么不许做"的那部分规则。
>
> **为什么放在仓库里**：这些规则原先只活在本机会话的 `AGENTS.md`（工作区级指令）中，而那份文件不随插件分发。换个会话、换个 agent、换台机器，工具还是那 19 个，但产出的东西会立刻走样。所以把它纳入版本控制，作为插件的业务基线。
>
> **与技能的关系**：`skills/*/SKILL.md` 是可执行的**操作手册**（怎么调、参数怎么写）；本文是跨技能的**口径约定**（为什么这么调、什么情况必须停）。两者冲突时，标了"硬规则 / 硬门"的那条优先；与代码里的硬门冲突时，以代码为准（代码拦得住的才是真门）。
>
> **脱敏说明**：本文件是公开仓库版本，已把具体客户名、项目名、地名、本机绝对路径替换为占位符（如"某商业项目""某市一学校"）。规则本身、数值、日期、教训一字未改——被替换的只是识别信息。
>
> **维护方式**：新增口径时改本文并注明日期与用户原话；只有当一个口径需要配套操作步骤时才写进技能，避免两处重复打架。

---

## 0. 分层：哪些是常驻、哪些是按需

理解这套口径最容易踩的坑，是误以为写进技能就等于生效。

| 载体 | 生效方式 | 内容 |
|---|---|---|
| 本机 `AGENTS.md` | 每轮常驻（system prompt） | 全部口径 |
| 技能 `SKILL.md` | **按需加载**（catalog 只暴露 name/description/whenToUse，正文要主动 load） | 操作步骤 + 少量硬规则 |
| 工具代码 | 每次调用强制执行 | 参数校验、付费门、票据门、单线路失败即停 |
| 本文 `docs/business-rules.md` | 人工/agent 查阅 | 全部口径的唯一真源 |

所以"写进技能"只解决"用这个技能时知道规矩"，不解决"不加载技能时也守规矩"。真正每轮必守的三类，必须落到代码硬门或宿主常驻指令里：

1. **付费与提交安全**（票据、单线路、失败即停、不自动补跑）——已在代码里。
2. **默认档位**（2.5 + 480p）——已在代码里（非默认必须声明 `user_explicit`）。
3. **构图与交付偏好**（景别克制、审阅页形态）——只能靠常驻指令或技能，见下节。

## 1. 视频生成模式（用户 2026-10-21 定，优先级最高）

1. **默认走全能参考（m2v / multimodal-to-video）。** 只要用户没有明确说"用首尾帧模式 / 必须首尾帧"，一律走 m2v，**不主动用 `first_last_frame`**；不因为素材是"一张起点图 + 一张终点图"、也不因为听上去像开场-收尾就自动切首尾帧。用户只是在描述"开场用 A、最后收到 B"，属于**内容描述**，不是模式指令。
2. **只有用户明确指出切换 / 必须使用首尾帧时**，才用 `first_last_frame`。这一条优先于一切默认推断。
3. **用户给的是一个整体时长**（如"一条 15 秒的视频"）时，就是**一条产物、一个节点、一次生成**。不得自行拆成多条 N 秒节点再拼；分段只写进同一条提示词的内部时间轴（T3 单一镜头 · 内部时间轴，或 T2 时间轴式）。只有用户明确要求"每条独立 / 单独审阅 / 逐条确认"，或素材之间确实无法放进同一条时，才拆多个节点，并在回复里说明为什么拆。
4. **画布直调的同一个默认**：有文字 + 任意参考素材 → `--mode m2v`；纯文字 → `--mode t2v`；`first_last_frame` 只在用户明确点名时使用。m2v 才支持视频/音频混合参考，首尾帧只吃图片。

### 1.5 景别克制（用户 2026-11-21 定，硬规则）

**单条任务的镜头以特写 / 中近景 / 中景为主导，尽可能克制全景。**

- 全景只在构图必需时使用（俯拍车位、空间蒙太奇收束这类不拍不行的），**单任务内全景不超过 1 个**。
- 能用中景解决的不用全景；能用特写解决的不用中景。
- 写提示词时**默认焦段 50mm / 85mm**；35mm 全景属于例外，要能说出为什么非它不可。
- 这条作用于成片构图，不改变 §1 的执行模式判定。

## 2. 视频默认档位（用户 2026-11-13 定，硬规则）

- **默认就用即梦 2.5 + 480p。** `generate_video` 不传档位时默认 `model_version=seedance_2.5`、`video_resolution=480p`；画布直调 `node create video` 不传 `model`/`resolution` 时工具自动补这两个值。
- **改用其它模型或分辨率，必须用户本人明确说了才调整。** 非默认模型要传 `video_model_selection_source=user_explicit`；非默认分辨率（非 480p）要传 `video_resolution_selection_source=user_explicit`。**代码里是硬门：不声明就拒绝提交。**
- **不得自行改档**：不为"画质更好""先试一下"升级到 720p/1080p/4k，也不从语料、示例、容量、失败回退自动换模型或换分辨率。
- 用户点名其它档位（如"用 2.0 VIP""要 1080p"）时照做，并在启动计划 summary 里写明模型与分辨率，随票据一起由用户批准。
- 例外只有测试通道：`test_submit_only` 强制最低成本模型 + 720p，只用于测试、不交付内容。

## 3. 生成任务分组：在执行脚本阶段定死（用户 2026-11-10 定，硬规则）

**把适合的镜头融合进同一个生成任务——这个决定在执行脚本（九列分镜表）阶段完成，不在提示词阶段做。**

- 执行脚本要把镜头圈成「生成任务」（＝后面一个节点 / 一段提示词），分组在本层定死；**提示词层只按组写，不得重新分组**。
- 每任务 **4–10 秒**（短剧线沿用 4–15 秒）、**2–4 镜**、**≥3 个景别**；超过 10 秒的连续长镜头按其规则单独处理（可 1 镜成任务）。
- **有人物的任务不跨场景**；必须换场时最多 1 次，且用人物局部特写做桥。
- 每任务参考素材 **≤9 张图**。
- 单句 **2 秒以内**的插入镜允许 **1 镜成任务**（不适用 3 景别）。
- 每个任务标注类型：**连续任务**（同空间内时间轴推进）／**快切组**（独立短镜、剪辑合成）。
- 写不下就回改执行脚本重新分组，再把下游提示词整组重出；不要在提示词层私自拆组。

## 4. 布光锁定与创作分工（用户 2026-11-10 定）

### 4.1 布光锁定

- **做任何布光锁定之前，先主动向用户要参考图**：一张整体图 ＋ 每个时段／光源各一张图。**没有图不要自己写。**
- **图由 Gemini 直接看**：Agent 不描述图内容、不代写布光文字；**一次调用**把整体图与所有分时段图一起给它，一次写完「整体风格锁定 ＋ 模块化布光锁定」。
- **Gemini 每次都是第一次接触**：brief 只给「片子的基本事实 ＋ 图序对应什么 ＋ 输出格式」，**不要塞元规则、既有规则解释、要点清单**——塞了只会让它混乱、把预算花在理解指令上。
- **布光锁定用纯英文**，维度参照（主光方向 → 软硬 → 侧逆光 → 空气 → 高光 → 阴影 → 材质 → 冷暖 → 禁止项）。风格化手绘动画要写成「手绘画面里的光」，不写 sensor / film grain / lens 这类实拍参数。
- 结构：整体风格锁定（全片通用一段）＋ 模块化布光锁定（白天／黄昏／夜晚／商店灯光等各一段，可独立拼接）；**拼接由 Agent 按任务完成**。
- Agent 只做两件事：**事实校准**（参考图里残留的具体物件改成片子实际场景）、**按任务拼装**。

### 4.2 创作分工

- **Gemini 只负责两样**：① 导演脚本；② 布光／风格锁定（看图写整体锁＋分时段模块）。
- **其余全部由 Agent 自己做**：执行脚本（九列分镜表＋生成任务分组）、提示词脚本（11 区块装配、素材绑定、常量块、逐镜画面与镜头行）——**这两层不调用 `creative_writer`**。
- 调用 Gemini 时 brief 只给「片子基本事实 ＋ 图序 ＋ 输出要求」；**有图必传**，Agent 不描述图内容、不代写。

## 5. 标准角色卡：按角色类型分线（用户 2026-11-06 定）

- **真人角色**——卡面是照片本人的写实呈现 → Gemini 线 `image_provider = comfly-gemini-flash-preview`
- **任何风格化角色**——插画 / 国潮 / 手绘动画 / 二次元 / 漫画等一切非写实形象 → GPT 线 `image_provider = comfly-gpt-image-2-4k`
- 判定只看「卡面是不是真人写实」：是 → Gemini，不是 → GPT。**风格化角色直接走 GPT，不要问**，也不要因为"角色卡默认走 Gemini"而落到 Gemini 线。
- 接入参考图时优先用 `batch_image` 的 `reference_images`（`generate_image` 的 `image` 通道在本机曾报 `image must be an array`，暂不可用）。
- 版式：上排四格底边齐平（第 4 格腰线截断边 = 前三格脚底），下排三张头肩同大、同顶线、裁到锁骨；卡面人物是照片本人（写实），发型/服装/配饰全部沿用照片。
- **这条 provider 规则不写进业务 Skill 包**（业务包对 provider 中立，校验会拒绝），只留在本文与仓库 AGENTS.md。

## 6. 场景卡三规则（用户 2026-11-07 定）

### 6.1 必须写明具体地点（真实名称）

- 场景卡提示词必须写明**所属城市 + 项目/建筑/场所的真实名称**。
- **不要只写泛化描述**（如"现代中式校园""商业综合体""某城市主干道"）——模型不知道画的是哪里，就会自己编造地名与招牌文字（实测把甲地的一所学校写成了乙地的另一所学校名）。
- 给出真实地点名即可把它当作**事实信息**交代清楚（"这是 XX 的 YY"），不需要再写"必须写出某某几个字"这类强制约束；模型知道是哪里后，招牌与标识会自然对上。
- 出现错字仍按后期贴字处理。

### 6.2 文字：两头都不管（作用于全部出图）

- **提示词里既不要写「禁止出现文字/不要可读文字」这类负面约束，也不要反过来强制「必须写出某某招牌字」。** 让模型按参考图的真实样貌自然生成——参考图里有招牌、路牌、校名、门头字就自然呈现，没有就不加。
- 只有**原图自带水印/台标**（素材站半透明水印）才要求"去掉水印"，不要把"去水印"扩大成"整幅无字"。
- 文字若出现错别字或乱码，**后期处理**（重绘/贴字），不在提示词层做正反向干预。
- 这条优先于历史上任何"画面无文字"或"必须带招牌字"的写法。

### 6.3 一律不带人物

- **场景卡一律不带人物**：不出现行人、游客、学生、骑行者、球员、家长、可辨认的人物剪影与背影（这些位置留给后期用路人卡合成）。
- 唯一例外：剧场观众席这类**纯氛围性、虚焦暗部**的观众轮廓可以保留，但不得出现可辨认的个人形象。
- 车辆、自行车、道具不算人物，正常保留。

## 7. 画布：命名与节点布局

### 7.1 新建画布先问名字（用户 2026-11-05 定，硬步骤）

- **先问名字，再建画布**：任何"新建画布"（`dreamina_canvas canvas create`，或第一次用 `video_group` 落一个新画布）之前，先单独问用户一次画布名称，并给出推荐模板：**项目名_文件名**。
- **Agent 自动补日期**：用户给名后按当天日期加 `YYYYMMDD-` 前缀。
- **已带日期就不重复加**：用户直接给 `20261105-xxx` / `2026-11-05-xxx` / `2026_11_05-xxx` 时原样使用。
- **模板只是推荐，不做校验**：用户给短名、只给项目名、纯自定义、带空格都照用，不得因为"不符合 项目名_文件名"而拒绝或反复追问。
- **用户不答 / 说"你定"**：Agent 按 `项目名_文件名` 自拟，直接建，不卡住等待。
- 复用已有画布时不需要问名字；只有"新建"这个动作才走本步骤。

### 7.2 节点布局（新建节点默认位置）

- **新建节点默认放在画布「最右侧节点的右边」，同一批从顶部向下排列。**
- 定位算法：先取当前所有节点的最右边界 `max(x + width)`，新列 `x = max_right + 620`；`y` 从 `0` 开始，每条 `+420`（第 i 条 `y = i * 420`）。
- 建节点时直接传 `--x` / `--y`；已建好的节点要重排时用 `node edit video --x --y`——**只传坐标**（元信息更新），读回确认 model / resolution / duration / references 未被重置。
- 一批超过 10 条时继续往下接，不另起新列。
- 取 `layout` 用 `node show`，一次传 `--node-id` **不超过 9 个**（超过服务端会以 invalid input 拒绝），分批取。

## 8. 出图交付（长期有效）

- **每批出图都必须交付审阅页**（`.html`，图片内嵌、逐张可勾选、底部「复制勾选名称 / 复制勾选路径」），不管用户这轮有没有提。审阅页与成品放在同一目录，一并给出；同时给总览拼图。
- 批量工具自带的 contact sheet 若把整图误拆成多宫格（自动检测误判），不要直接交付，改为自建审阅页，保证每张候选按整图出现一次。
- **用 PIL 画任何中文标注必须显式加载中文字体**：`ImageFont.truetype(r"C:\Windows\Fonts\msyhbd.ttc", size)`。不传 font 时 PIL 用默认位图字体，不含中文字形，`ImageDraw.text()` 会把中文画成方块/乱码（联系表、总览图、标注图都会中招）。生成后要回读确认中文可读。
- **不要用 PowerShell 的 `Get-Content` / `Set-Content` 改写含中文的文件**（会按 GBK 读入再按 UTF-8 写出，整篇变乱码）。一律用 Python `open(..., encoding="utf-8")` 或 write/edit 工具改写；改完必须回读校验中文文本正常。

## 9. 扩图任务必须交付「手动拉条对比」（用户 2026-11-16 定，长期有效）

- **所有扩图任务都必须交付「手动拉条对比」**，不是只给单张成品、也不是只给静态并排长图。范围包括：左右/上下补画幅、白底扩边、白底+AI 填充、程序化扩边、AI 图生图扩图、以及同一素材的任何比例改版。
- **「手动拉条」＝可拖动的滑块对比页（HTML）**：画面中央一条可拖动的竖向拉条，左边显示 A、右边显示 B，用户手动左右拉看差异；图片必须 base64 内嵌（不依赖相对路径，双击即开），支持鼠标拖动、触摸拖动、键盘 ← → 微调。
- 页面必须带**全版本缩略图条**：每个版本一张缩略图 + 「设为左 / 设为右」按钮，任意两版可两两对比；当前选中的两版在缩略条上高亮。
- 版本清单与排列顺序固定：**原图 → 程序化扩边 → AI 候选（按编号）→ 白底模板 → 白底+AI 填充候选**，标注版本名 + 尺寸 + 处理方式。
- **新增版本就要更新这个拉条页**（补跑、换提示词、换方案、换尺寸都算），拉条始终是全版本汇总，不要只截取本次新增的那几张。
- 拉条页与成品放同一目录，一并给出；另附一张静态等高并排长图 PNG 作为「一眼看全」的补充（中文标注必须显式加载 `msyhbd.ttc`，生成后回读确认中文正常）。
- 交付时在回复里给出每一版的差异判断（尺寸 / 处理方式 / 建筑是否原样），帮用户直接选。

## 10. 审阅页「复制按钮」硬要求（用户 2026-11-17 定，管线级）

- **所有审阅页的「复制名称 / 复制路径 / 复制名称+路径」必须双击（`file://`）就能用**，不许出现「点了没反应」。
- **实现顺序固定**：在点击的同步调用栈里**先** `document.execCommand('copy')`（临时 textarea → `focus()` → `select()` → `setSelectionRange()`），失败再退 `navigator.clipboard.writeText`，仍失败则弹出已全选的手动复制框（提示 Ctrl+C）。
- **禁止反过来**：先调 clipboard API 时，`file://` 与受限 iframe 会 reject，而 reject 回调已脱离用户手势，此时 execCommand 同样被拒——这正是「复制按钮没反应」的根因。
- **落地位置**：审阅页生成脚本里的 `inject(html)`（幂等），任何自建审阅页脚本在写文件前必须调用一次。
- **验收**：生成的 HTML 里 `COPY-FIX-2026-11-17` 恰好 1 处；页面内所有 `<script>` 块用 Node `vm.Script` 编译 0 错误；`.card` 的 `data-label` / `data-path` 数量与卡片数一致。

## 11. 生成启动门：视频必带票据（用户 2026-11-13 定，代码级硬门）

**默认流程：只建节点，不自动开始。**

- `generate_video` 不带 `auto_start` 时只做「上传素材 → 建图片节点 → 保存视频节点」，**不报价、不确认、不运行、不扣费、不需要票据**；节点铺好后由**用户在画布上手动点「开始生成」**。Agent 不得主动调起自动生成。
- **自动开始是手动触发**：只有用户明确表示「自动开始 / 自动生成 / 直接提交」时才传 `auto_start=true`，且：① 必须同时传 `auto_start_reason`（记录用户原话）；② 节点全部建好后走「登记计划 → 真人终端批准 → 拿 `lt_xxx` → 带票提交」；③ 提交的是计划里那一批，票据一次性、30 分钟过期、范围锁定，提交即消费。
- **视频没有票据就提交不了**：`generate_video` 与 `dreamina_canvas` 的视频提交（`node run` / `--run`）在插件代码里强制校验一次性票据 `launch_ticket`；缺失、过期、工具不符、超出范围都会直接拒绝。
- **图片不过门**：`generate_image`、`batch_image start`、`upscale`、`node create/edit image` 照常直接做——出图是迭代活，不为它加人工确认（仍受容量池 / 预算 / 失败即停的既有约束）。

### 11.1 画布节点提交的两个实测坑（2026-11-20）

- **`launch_ticket` 必须是工具顶层参数**（与 `command` / `action` 同级），**不能放进 `args`**。插件源码读的是工具输入对象顶层，而 `args.args` 才是 CLI flags——两者不是同一个东西。放错位置的表现就是永远报「缺少 launch_ticket」。
- **积分必须走 `credit_token`，不能传 `credit_ceiling`**：`credit_ceiling` 会被转成 CLI 的 `--credit-ceiling`，而 `node run` 的 CLI 不支持这个 flag，直接 `Invalid flag`。正确链路：`node quote` → `node confirm --credit-ceiling N` 拿 `credit_token` → 把 `credit_token` 放进 `args`（CLI 支持 `--credit-token`）。
- **票据状态文件在双层运行目录下**：插件按 `<session.cwd>/.dsh-media-private/launch-gate/state.json` 读取；当会话工作目录本身就叫 `.dsh-media-private` 时，实际路径会再套一层。用 `scripts/launch-gate.mjs` 登记/批准时把 `--private` 指到插件真正读取的那一层，否则登记的票插件读不到。
- 可复制的调用形态：
  `dreamina_canvas(command="node", action="run", launch_ticket="lt_xxx", args={project_id, node_id, credit_token})`

### 11.2 铁律

- **票据只能真人生成。** Agent 没有 TTY，`approve` 会被拒绝；用管道喂确认词、用脚本绕过 TTY 检查同样无效——不得尝试。
- **不得代批、不得复用、不得伪造票据**；一张票只覆盖计划里那一批，提交一次即作废。
- **提示词 / 素材 / 画布任何改动后，旧票据作废**，必须重新登记计划并重新批准。
- **用户口头说"自动开始"不算**：`auto_start_reason` 只是留痕，真正的许可只有终端里那一次 `approve`。
- 用户没说自动开始时的标准动作：建完节点就停，把 node_id 与画布链接给用户。
