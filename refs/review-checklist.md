# 视频 Skill 入库审核清单

## 来源完整性

- 原始文件未被覆盖。
- 每个来源已记录文件名、编码和 SHA-256。
- 有价值的专业经验和社区经验均可在标准包中定位。
- 删除的只有包装、日志、凭据和不可执行噪声，并已在报告中列出。

## 契约

- `skill_id` 与目录和 frontmatter 一致。
- 至少有一项图片、视频或音频参考。
- 每项素材的类型、角色、数量、顺序和必选性明确。
- 每个素材槽都有时长节奏规则；规则类型、硬性/推荐、上下限、来源、置信度和理由均已审核。
- 来源未明确节奏时，自动补充规则已标记为 `curator_default`，没有伪装成来源事实。
- 未启用 `text2video`。
- 示例没有参与契约推导。
- 没有 provider、模型、分辨率、轮询或下载策略。

## 意图路由

- `routing.json` 描述用户想创作什么，而不是用户当前拥有什么素材。
- 别名、用途、主体、风格和叙事模式能区分相近 Skill。
- 排除意图不会错误阻断该 Skill 的核心用途。
- 素材要求仍只由 `contract.json` 定义。

## 创作知识

- 用户当前明确指令具有最高优先级。
- 强制规则和建议规则已经分开。
- 社区经验具有适用条件和证据等级。
- 失败案例同时记录规避或修复策略。
- 专业英文术语可以保留，并提供必要中文释义。
- 模型版本只作为历史来源信息。
- 正例满足 `example-quality-benchmark.md` 的输入、绑定、时间推进、镜头动作、物理结果与结尾完整度。
- 反例同时包含错误写法、失败表现、违反规则和修正策略。
- 边界案例同时包含触发条件、仍适用规则、停止或降级项和处理方式。
- 优秀 Skill 仅作为结构与质量基准，未把其题材、镜头数量、风格或契约复制到目标 Skill。

## 包结构

- `SKILL.md` 简洁且描述包含触发条件。
- `contract.json` 通过确定性验证。
- `agents/openai.yaml` 与 Skill 名称一致。
- 四份知识文档存在且没有模板标记。
- 不包含绝对路径、凭据、日志或运行产物。

## 发布确认

向用户明确展示：

- 将发布的名称和 `skill_id`；
- 所有素材槽；
- 合并、删除、降级或隔离的规则；
- 尚存歧义；
- 与现有 Skill 的重复情况；
- 验证结果。

只有用户明确确认这份报告后才能发布。
