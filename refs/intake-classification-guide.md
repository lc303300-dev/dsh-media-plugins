# 入库知识分类指南

## 决策顺序

对原始资料中的每条信息依次询问：

1. 它是否决定必须提供什么素材、数量、顺序或绑定方式？是则进入 `contract.json`。
2. 它是否是每次运行都必须执行的流程？是则精炼后进入 `SKILL.md`。
3. 它是否描述如何获得更好的视觉、镜头、动作、声音或连续性？是则进入 `creative-guidance.md`。
4. 它是否来自社区实践、经验总结或未经完全验证的观察？是则进入 `community-experience.md`。
5. 它是否描述错误表现、原因和规避方法？是则进入 `failure-cases.md`。
6. 它是否只是一个输入输出案例？是则进入 `examples.md`。
7. 它是否只与旧 provider、模型版本、CLI 或具体项目有关？作为来源背景隔离，不能进入执行契约。

## 契约与建议的区别

“图片1必须是角色四视图”是契约，因为缺失时无法正确绑定身份。

“低机位通常更显宏伟”是创意建议，不是契约。

“社区反馈在复杂建筑中慢速推进更稳定”是有条件的社区经验，不是强制镜头规则。

“示例使用上海地标”只是示例，不代表 Skill 必须用于上海。

## 社区经验记录格式

每条经验使用：

```markdown
### 经验标题

- 结论：原意完整的经验结论。
- 适用条件：何时采用。
- 不适用条件：何时不应采用。
- 证据等级：`repeated`、`single-report` 或 `source-claim`。
- 来源背景：社区、作者说明或历史模型；不包含凭据和私有链接。
```

不要为了“规范”而删除不确定经验；应降低其证据等级并保留适用条件。

## 冲突处理

以下冲突必须进入用户审核：

- 同一素材同时被声明为必填和可选；
- 同一镜头同时要求硬切和一镜到底；
- 同一图片同时被声明为严格首帧和严格尾帧；
- 不同段落给出不同素材数量；
- 社区经验与作者硬规则冲突；
- 示例与正文契约冲突。

默认裁决原则：正文明确契约优先于示例；用户明确决定优先于所有来源。仍无法确定时不得发布。

## 经验保留报告

入库报告至少统计：

- 提取的确定性契约项；
- 专业创意规则；
- 社区经验；
- 失败案例；
- 正例、反例和边界案例；
- 被隔离的旧 provider/模型/项目规则；
- 未解决冲突。
