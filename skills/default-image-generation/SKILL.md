# 默认图片生成（统一媒体路由器）

1. **比例必填**：调用 `generate_image` 前，要求用户明确选择 8 个支持比例之一：`21:9`、`16:9`、`3:2`、`4:3`、`1:1`、`3:4`、`2:3`、`9:16`。用户未明确时**停止并询问**；绝不从参考图方向、提示词、历史轮次、文件名或供应商默认推断。通过结构化 `image_ratio` 字段传入。
2. **分辨率与像素尺寸**：默认线路 GPT 2.5 **只出 4K**，传 `1K`/`2K` 也会按 4K 执行（不降级）。用户给出具体像素尺寸（`1920x1080`、`1080x1920`、`2048x2048` 等）时，直接把它填进 `image_ratio`，工具会换算成最接近的标准比例并按 4K 出图；也可以自行换算后传标准比例 —— 对照：`1920x1080`/`1280x720`/`3840x2160` → `16:9`（3840x2160）；`1080x1920`/`720x1280`/`2160x3840` → `9:16`（2160x3840）；`1080x1080`/`2048x2048` → `1:1`（2880x2880）；`1620x1080` → `3:2`（3520x2352）；`1440x1080` → `4:3`（3312x2480）；`1080x1620` → `2:3`（2352x3520）；`2560x1080` → `21:9`（3840x1648）；其他尺寸按宽高比取最接近的 8 比例之一，横竖方向不得颠倒。`image_resolution` 只对 Gemini / Dreamina 有意义：Gemini 线路现在是 **2K-only**（传 `1K`/`4K` 也按 2K 执行），Dreamina 缺省 1K。像素尺寸也接受 `1920×1080`、`1920*1080` 等写法，同样自动换算成最接近的标准比例。
3. **线路选择**：不主动询问供应商。默认线路是 `comfly-gpt-image-2.5`（Comfly `gpt-image-2.5-sunburst`，提交 4K 具体像素尺寸）。仅当用户在当前请求中明确点名一个受支持且无歧义的线路（`comfly-gpt-image-2.5`、`comfly-gpt-image-2`（兼容别名）、`comfly-gemini-flash-preview`、`dreamina-image`）时，才通过 `image_provider` 传入该线路；指定后只走该线路、失败不回退。不要使用未注册线路（如 `apimart-gpt-image-2`、`google-gemini-image`），也不要点名模糊名称（如"Gemini"在 Comfly 与官方 Google 之间是歧义的）。
4. 传非空 `prompt`；图生图时把参考图路径按语义顺序放入 `image` 列表。
5. 不要把 API 参数暴露给用户；默认回退顺序、并发、超时由路由器内部处理。默认串行回退顺序：comfly-gpt-image-2.5 → comfly-gemini-flash-preview → dreamina-image，**但只有"错误类"失败（401/403、402/429、5xx —— 这条线路当场拒绝或生成不了）才换下一条线路**；超时（90 秒时间盒用尽）与下载失败**直接判失败**，因为请求已经发出、可能已计费，换线路等于对同一张图付两次钱（下载失败只在同一个 URL 上重试）。单张总预算 90 秒：单次尝试、整任务与批量的每股基准是同一个时间盒。
6. 每次调用都是外部付费操作：生成前确认用户意图；不做投机性生成。
7. 返回结果后直接使用工具返回的路径；不要用原始 Windows 反斜杠路径拼 Markdown 链接。
8. 提交结果不确定（needs_review）时禁止自动重试或换供应商重试，提示用户人工核对后台。
9. 参考图会自动做 EXIF 方向归一化与最长边 1920px 等比缩放后提交，绝不覆盖原图。
10. **本线路只对数量与速度负责**：生成后不做质量检查——不逐张 `read_image`/`describe_image` 验收，不做审美、一致性或尺寸判断，不自动重生成。成功即按返回路径交付；只有工具返回失败或 `needs_review` 时才如实上报。
