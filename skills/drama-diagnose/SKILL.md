# 诊断（大纲 → 信息点 + 四类问题 + 时长核算）

> 规则依据：`drama-tvc-prompt/references/outline-to-jimeng-pipeline.md` §2；执行协议：`guided-production-flow.md` Step 0。

## 输入

| 字段 | 必要性 | 说明 |
|---|---|---|
| 脚本正文 | 必需 | docx / md / 纯文本 |
| 时长目标 | 必需 | 若脚本自带时间标注，**一律忽略并推翻** |
| 台词归属 | 强烈建议 | 缺失时按上下文推定并标注 |
| 素材现状 | 强烈建议 | 是否已有场景卡/角色卡/音色 |
| 卖点/信息点 | 若客户有 | 房地产类必须给 |
| 禁止项 | 视项目 | 直接进【限定】与【特殊要求】 |

## 做四件事

1. **读全文**（docx 用 python-docx 提取，md/txt 直读）。
2. **拆信息点清单**：台词逐句拆成信息点（一句通常 2–4 条），编号。
3. **四类诊断**：

| 诊断项 | 典型症状 | 处理原则 |
|---|---|---|
| 时长/台词量不匹配 | 55 秒塞 15 句长台词 | 时长是**核算输出**，先算台词需要多少秒 |
| 台词书面化 | 大段书面语、术语堆叠 | 口语化，但信息点一个不许丢 |
| 逻辑/常识硬伤 | 动线不成立、场景缺失 | **优先动画面，不动台词** |
| 术语/品牌口径 | 面积、距离、全称写错 | 以客户资料为准，不自行修正 |

4. **时长核算**：`台词字数 ÷ 4.5 字每秒 + 动作/空镜秒数 = 建议总时长`。

## 产出：`00-诊断报告.md`

```markdown
# 诊断报告
## 一、信息点清单（共 N 条）
| # | 所属场次 | 信息点 | 出处句 |
## 二、四类问题
| 类型 | 问题 | 建议处理 |
## 三、时长核算
台词 X 字 ÷ 4.5 = Y 秒；动作/空镜 Z 秒；建议总时长 Y+Z 秒
## 四、需要你确认的三件事
```

## 验收

- [ ] 信息点清单可逐条核对，条数写在标题里
- [ ] 四类问题每类至少扫过一遍（没有就写"无"）
- [ ] 时长是算出来的，不是抄脚本的
- [ ] 只问必要问题（一次 ≤3 个），能从文件读到的绝不问

## 常见返工

- 「你默认都没有」→ 别假设有素材，没有就说没有，并给"要准备什么"清单。
- 「时间不对」→ 用信息点法重算，不要相信脚本文档里的时间标注。
