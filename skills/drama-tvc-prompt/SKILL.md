> **本技能 = 社区项目方法论 + 即梦实战规范**，不是自由发挥。

## 完整链路

```
文字脚本
  ↓ ① 山音五步工作流
九列分镜表（镜号/时长/摄影角度/景别/画面内容/场景/声音/备注/叙事目的）
  ↓ ⑥ 镜头级渲染（本段 2–4 个分镜行 → 带时间戳的逐镜行；动作/对峙两套模式）
  ↓ ② 即梦 10 区块提示词（分镜表 + 逐镜行 → 每段一个任务）
即梦 / Seedance 提示词
  ↓ ④ 画板批量制片流程
成片
```

## 生产流程：Agent 骨架 → Gemini4 重写 → Agent 规范（唯一标准流程）

**2026-10-18 固化**。四步线性流程，完整规范见 `references/production-pipeline.md`：

```
① Agent 用山音九列规范搭骨架（不调 LLM，结构由 Agent 保证）
        ↓
② Agent 做 12 项逻辑自检（不通过不进下一步）
        ↓
③ Gemini4 重写（只调一次成功；超时按输出字数动态计算 120–300s → 失败降基础档 → 再失败 Agent 自润）
        ↓
④ Agent 验收并规范化为成果（md + docx）
```

**为什么不是「全部交给 LLM」**：山音九列是确定性结构，Agent 写得最快最准；Gemini4 只负责
语言润色与参数补充；最终必须 Agent 验收——否则 Gemini4 会漏镜、改时长、偏离骨架。

**成本纪律**：
- 整套流程**只调用 Gemini4 一次成功**；每档只尝试一次，不重试
- **超时按输出字数动态计算**（thinking-high 120–300s，基础档 60–150s），到点即降档
- 全部失败**不报错**，Agent 基于骨架自己润色（骨架本身已是完整产物）

**文本生成引擎**：需要 LLM 参与的只有 Step 3。其余步骤由 Agent 直接产出，更稳、更快、更省。

**Step 3 档位规则（2026-10-18 调整，关键）**：

> **要「想」的用 thinking-high，要「填」的用基础档。**

| 产出 | 档位 |
|---|---|
| 剧本创作 / 剧本重写、执行脚本（分镜表）、导演定调 | **thinking-high**（`gemini-4-argon-thinking-high`） |
| **即梦提示词**、营销文案、文章 | **基础档**（`gemini-4-argon`，快 10–20 倍） |
| 故事 | 长文 high / 短文 base |

thinking-high 单次 77–188 秒；基础档 4–12 秒（几百字）。**写提示词绝不要用 high**。

**Step 3 调用纪律**：
- 走 `creative_writer` 工具（kind=script/prompt），或直连 comfly API（同一模型）
- `maxTokens` 必须足够（32768），否则长文会被截断成空回复
- 长任务用后台 job，别阻塞对话
- **硬门提醒**：`prompt_batch set_prompts` 会检查最近 24 小时有无 `creative_writer` 记录
  （kind=prompt/script/story/copy），没有则整次拒绝；确实要手写时显式传 `allow_manual_prompts: true`

## 两段式工作流（内容层）

### 第一段：剧本 → 九列分镜表（山音方法）

严格按五步，每步暂停等用户的 `[通过 / 修改 / 自检]`：

1. **导演定调** —— 六维定调法（情绪/类型/动作/题材/形式/社会）→ 七项视听决策 + 意象体系
2. **节奏规划** —— 双轨节奏 + 镜头组划分 + 节奏诊断
3. **剧本微调** —— 视听化修正 + 四焦点微调（表演/台词/画面/意象）
4. **分镜拆解** —— 叙事目的分析 → 九列分镜表（分批输出，不一次全片）
5. **输出 xlsx**

详见 `references/shanyin-director-method.md`。

### 第二段：分镜表 → 即梦提示词（分块生成）

1. **换算任务数**：分镜表按 cut 算，AI 按任务算（单任务 4–15 秒、可含 2–4 个**切点明确的**镜头）
   - 60 秒短片 ≈ 15 cut ≈ **6–10 个生成任务**
2. **分块生成**（详见 `references/production-pipeline.md` Step 3.5）：
   - **【布光锁定】**：整片 1 次生成，N 段逐字复用（保证影调统一）
   - **【故事背景】+【画面内容】+【镜头】+ 分镜逐镜行**：每段 1 次（可批量并行）
   - **其余 7 块**（风格/参考/设定/特殊要求/导演/一致性/限定）：Agent 拼装
3. **逐镜行展开（⑥ 镜头级渲染，别跳过）**：把本段对应的 2–4 个九列分镜行展开成带时间戳的逐镜行，
   写进【镜头】的「分镜：」子区。**先判动作模式还是对峙模式**，两套规范完全不同
   （规则见 `references/shot-level-rendering.md`）。这一步决定成片节奏能不能对上分镜表。
4. **素材绑定**：角色卡/场景图/音色 → 画板节点 → `{{node:xxx}}` 引用
   - 逐镜行里的 `@角色名` 只是**称谓**，真正的绑定仍是裸标签 `图片N`
   - 素材文件**不要用角色名命名**（否则提示词里出现角色名会被判为文件名泄漏而拒绝）
5. **画板生成**：按 AGENTS.md「画板批量制片流程」

详见 `references/jimeng-drama-template.md`（区块写法）与 `production-pipeline.md`（流程）。

## 关键换算表（分镜表 → 提示词）

| 九列分镜表 | → 即梦 10 区块 | 谁负责 |
|---|---|---|
| 镜号 / 时长 | 决定每任务装几镜、总时长 | Agent 分块 |
| **摄影角度 / 景别 / 备注（运镜）** | **【镜头】逐镜行**：时间戳闭环 + 光圈(景深) + 焦段(景别) + ≥2 项摄影语言 + 动作结果（**2–4 镜/任务**） | Gemini4，规则见 `shot-level-rendering.md` |
| 画面内容 | 【画面内容】主体（只写可见动作与台词流） | Gemini4 |
| 场景 | 【参考】场景素材（仅为场景参考） | Agent 拼装 |
| 声音 | 【设定】（有/无台词）+【限定】（禁音乐/音效） | Agent 拼装 |
| **叙事目的** | **不直接进提示词**，但决定这段的情绪与镜头选择 | — |

## 铁律（来自社区项目，优先级最高）

- **绝对不要**：写心理描写、写括号暗示、在画面内容写摄影机拍不到的东西、说教、AI 腔比喻
- **必须**：画面内容只写可见动作；声音列只写可听声音；叙事目的用客观分析语气并具体到视听手段；台词口语化
- **工作流纪律**：不跳步，每步暂停等 `[通过 / 修改 / 自检]`
- **一个镜头一行**：硬切/叠化/跳切算新镜号；推拉摇移/焦点转换/角色进出画不算

## 与其他技能的边界

| 场景 | 用哪个 |
|---|---|
| 单条视频、只要一个提示词 | `video-director-prompt`（官方 5 模板） |
| **一条片子多段、要剧本→分镜→提示词全链路** | **本技能** |
| 多素材批次、逐段确认 | `video-prompt-orchestrator`（批次模式） |
| 业务 Skill 治理 | `skill_curator` / `codex-cs-skill-curator` |

**分段骨架**仍以 `video-director-prompt` 的官方模板集为唯一真源；本技能的 10 区块是**叙事层**写法，两者可叠加。
