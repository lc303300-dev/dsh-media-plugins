# 创意 Manifest（一次调用完成整片创意内容）

> **2026-10-19 起，短剧的创意内容走批处理**：Agent 组装一份 manifest → **1 次 `creative_writer` 调用** →
> 按 `===Txx===` 解析 → 机械校验 → 拼常量块 → 出完整提示词。
>
> **为什么改**：旧规则是「每段 1 次」（9 段 = 9 次），依据是 2026-10-18 的「9 段一次生成实测两次
> SSL 断连（请求太大）」。那是 **urllib 直连 comfly** 时代的问题；现在走 `ctx.llm.stream`，
> 实测 9 段 / 27 镜 / 6569 字 **一次成功**，时间戳闭环 9/9、台词零缺失、违规写法 0、**无后段衰减**。
>
> **顺带的好处**：批量版每段 524–970 字，正好落在 `shot-level-rendering.md` 的 500–900 字预算内；
> 分段时 Agent 把 200 字场景描述喂给每段，Gemini4 会全铺进【画面内容】→ 1200+ 字，反而超预算。

---

## 一、调用粒度

| 片长 | 段数 | 调用次数 | 说明 |
|---|---|---|---|
| 短片 | ≤10 段 | **1 次** | 一次给全片视觉资产 + 段落表 + 台词 |
| 中片 | 11–20 段 | 2 次 | 按 ≤10 段切批 |
| 长片 | >20 段 | ceil(段数/10) 次 | 每批独立 manifest |

**为什么上限 10 段**：批处理失败要**重跑整批**，批越小代价越低。单批连续失败 2 次再降为每段 1 次。

**不要为了"省调用"把 20 段塞进一次**：输出会超过 15000 字，截断风险与格式跑偏风险都会上升。

---

## 二、输入 manifest（填完直接作为 `context` + `brief`）

### 2.1 项目定位

```
项目：《[片名]》[品牌/项目名]短剧，[类型]，[风格基调]。
全片 [总时长] 秒 / [总镜数] 镜 / [段数] 段。
```

### 2.2 视觉资产

**角色 + 换装点**（写明每段穿什么，换装要标在段号上）：

```
【角色与换装】
[角色A]：[日常服装]；[段X]起为[另一套]。
[角色B]：[服装]；[段Y]起换回[另一套]。
[角色C]：[服装]。
```

**场景实景**（Agent 必须看图后转译成文字——材质 / 家私 / 光位 / 色调，不要只写"客厅"）：

```
【场景实景】
S01 [场景名]：[色调]；[地面材质]；[左侧]；[中间]；[右侧]；[后墙]；[顶面/光源]。
S02 ……
```

> 这一节是**视觉贴合的命门**。只写「会所大堂」Gemini4 会凭空想象；写出「金色金属竖向格栅屏风、
> 青色釉面葫芦雕塑、深色高反射大理石」它才会写对。

### 2.3 结构骨架（段落表）

```
【N 段：时长 / 镜头表 / 台词】
===T01a=== [场景名] [时长]s
镜1 [起-止s] [焦段][景别] [机位]：动作要点
镜2 ……
台词：[角色]"台词" / [角色]"台词"

===T01b=== ……
```

镜头表的时长 / 景别 / 机位由 **Agent 定**（来自九列分镜表），Gemini4 不得改动；动作要点只给
"这个镜头要发生什么"，描写交给 Gemini4。

### 2.4 台词原稿

台词**逐句原样**写进段落表（一字不改）。标点、口语、方言都保留。

### 2.5 输出要求（固定段落，可整段复用）

```
写一部短剧 N 个段落的即梦提示词创意内容。**一次性输出全部 N 段**，按下面严格格式：

每段以小标题开始：`===T01a===`（任务号照抄，共 N 个：……）
然后是该段的两个区块：
【画面内容】连续画面流 + 台词流，不写"镜头1"这类编号，只写摄影机拍得到的动作、表情、视线、台词。
【镜头】先一句机位策略，再「分镜：」逐镜行，格式：镜头一（0-2.0秒）：光圈 f/4（中等景深，背景轻微虚化），焦段 35mm（全景），平视（eye-level）固定拍摄（static shot）；动作与结果。

硬要求：
1. 台词一字不改，原样写进【画面内容】；不要在【镜头】里重复台词。
2. 每段的镜头时长、景别、机位严格按给定镜头表，不得改动。
3. 时间戳从 0 开始，首尾相接，末镜结束在该段总时长。
4. 不写心理描写、不写括号暗示、不用 Markdown 加粗、不写风格词与画质词。
5. 中文输出，只给这 N 段，不要解释、不要总结。
```

### 2.6 全片级约束（容易翻车的事，写在 manifest 末尾）

```
【补充约束】
- [人物关系/站位]：如「爸爸站球台一端、女儿站另一端，隔台面对面，不是并排同一侧」
- [道具状态]：如「对打阶段共两只球拍；妈妈接过女儿那只后女儿手上不再有球拍」
- [空间与安全]：如「泳池段母女始终在岸上不入水」
- [背景人物]：如「公共空间可有一两位成年住户中后景虚化，不直视镜头、不与主角互动、不遮挡主角；私宅绝对无其他人」
```

## 三、输出契约

**分段标记**：`===T01a===` 独占一行，任务号与 manifest 一致。
**区块标记**：【画面内容】/【镜头】各一段，顺序固定。
**逐镜行**：`镜头N（起始-结束秒）：光圈 f/x（景深），焦段 xxmm（景别），机位（English）；动作与结果。`

Agent 解析规则（确定性）：

1. 用 `^===(\w+)===$` 切段 → 得到 `{任务号: 正文}`
2. 每段内用 `【画面内容】` / `【镜头】` 切区块
3. 从【镜头】里用 `镜头[一二三四五六七八九十]+（(\d+(?:\.\d)?)-(\d+(?:\.\d)?)秒）` 抽时间戳

## 四、Agent 标准动作（这就是 Agent 在这个环节的全部工作）

```
① 组装 manifest（项目定位 / 视觉资产 / 段落表 / 台词 / 输出要求 / 全片约束）
      ↓
② 1 次 creative_writer（kind=prompt，thinking=base，length=long）
      ↓
③ 按 ===Txx=== 解析成 N 段
      ↓
④ 机械校验（段数 / 顺序 / 时间戳闭环 / 镜数 / 台词逐句 / 违规写法）
      ↓  不通过 → 只用「这一批」重调（不重跑已通过的部分）
⑤ 拼常量块（【风格】【参考】【设定】【特殊要求】【导演】【一致性】【限定】）
      ↓
⑥ 出完整提示词（审阅版 + 可提交版，见 production-pipeline Step 4）
```

**注意**：
- 视觉资产那节必须**看图后转译**，不能只写场景名
- 台词必须**原样**进 manifest，Agent 不得"顺手润色"
- 校验不通过时，先判断是 Gemini4 的错还是 Agent 骨架的错（时长/镜数错通常是 Agent 的）

## 五、机械校验（可直接跑）

存成 `verify_manifest.py`，参数为产物 md 路径。校验项：段数/顺序、时间戳闭环、镜数、
台词逐句、违规写法。

```python
# -*- coding: utf-8 -*-
import re, sys, json
F = sys.argv[1]
t = open(F, encoding="utf-8").read()

# —— 期望值：从 manifest 抄（段时长、镜数、台词）——
EXPECT = {"T01a": (5.5, 3), "T01b": (8.5, 4)}          # 换成实际段落表
LINES  = {"T01a": ["台词1", "台词2"], "T01b": ["台词3"]}
CN = {"一":1,"二":2,"三":3,"四":4,"五":5,"六":6,"七":7,"八":8,"九":9}

parts = re.split(r"^===(\w+)===$", t, flags=re.M)
blocks = {parts[i]: parts[i+1] for i in range(1, len(parts), 2)}
rows, ok = [], True
for task, (dur, nshots) in EXPECT.items():
    body = blocks.get(task, "")
    ts = [(CN[m.group(1)], float(m.group(2)), float(m.group(3)))
          for m in re.finditer(r"镜头([一二三四五六七八九十]+)（([\d.]+)-([\d.]+)秒）", body)]
    probs = []
    if not ts or ts[0][1] != 0.0: probs.append("首镜非0")
    for k in range(1, len(ts)):
        if abs(ts[k][1] - ts[k-1][2]) > 1e-9: probs.append(f"断点{ts[k-1][2]}→{ts[k][1]}")
    if ts and abs(ts[-1][2] - dur) > 1e-9: probs.append(f"末镜{ts[-1][2]}≠{dur}")
    if len(ts) != nshots: probs.append(f"镜数{len(ts)}≠{nshots}")
    miss = [l for l in LINES.get(task, []) if l not in body]
    if miss: probs.append(f"缺台词{miss}")
    if probs: ok = False
    rows.append({"task": task, "closed": not probs, "probs": probs, "chars": len(body.strip())})

prompt = "\n".join(blocks.values())
viol = {
    "fps/帧率": len(re.findall(r"fps|帧率", prompt, re.I)),
    "4K/1080p/720p": len(re.findall(r"\b4K\b|1080p|720p", prompt, re.I)),
    "管道符": len(re.findall(r"[｜|]", prompt)),
    "@图片N/参考图片N": len(re.findall(r"@\s*图片\s*\d|参考\s*图片\s*\d", prompt)),
    "加粗": prompt.count("**"),
}
print(json.dumps({"ok": ok and sum(viol.values()) == 0, "rows": rows,
                  "violations": viol, "blocks": len(blocks)}, ensure_ascii=False, indent=1))
```

**判定**：`ok == true` 且 `violations` 全 0 才进入拼装；否则按「批」重调。

## 六、实测基准（2026-10-19 · 《周末，听谁的？》）

| 指标 | 1 次批处理 | 9 次分段（旧法） |
|---|---|---|
| 调用次数 | **1** | 9 |
| 输出字符 | 6569 | 约 13000 |
| 每段字符 | 524–970 | 1200–1500 |
| 时间戳闭环 | **9/9** | 9/9 |
| 镜数准确 | **27/27** | 27/27 |
| 台词完整 | **全** | 全 |
| 后段衰减 | **无** | — |
| 违规写法 | **0** | T02 混进过「4K高画质」 |

manifest 规模：项目定位 ~200 字 + 视觉资产 ~600 字 + 段落表 ~1400 字 + 台词 ~200 字 + 输出要求 ~300 字
+ 全片约束 ~200 字 ≈ **2900 字**，加输出 6569 字，一次调用约 60–90 秒（base 档）。

## 七、常见失败与处理

| 现象 | 判断 | 处理 |
|---|---|---|
| 段数少 / 任务号错 | 输出被截断或模型漏段 | 只重调这一批；批太大就切小 |
| 时间戳断点 / 末镜不等于时长 | 通常是 **Agent 骨架**错了（段落表时长与镜头表不自洽） | 先查段落表，不要怪 Gemini4 |
| 台词少字 / 顺序乱 | Gemini4 自由发挥 | 重调该批，并在 manifest 里把台词单独加粗强调 |
| 镜数多于段落表 | Gemini4 自行加镜 | 重调该批，或接受后由 Agent 合并 |
| 出现「4K高画质」等规格词 | Gemini4 把风格/画质写进叙事区块 | Agent 验收删除（不必重调） |
| 每段字数明显超 1000 | manifest 里场景描述太长 | 精简视觉资产（只留辨识特征），或让它分段落写 |

**不要**因为单段格式小瑕疵重跑整批——验收环节能改的就改，只有「结构错/台词错/段数错」才重调。
