# 镜头级渲染：九列分镜表 → 逐镜头提示词

> **定位**：本技能三层里的**中间层**。上游 `shanyin-director-method.md` 产出九列分镜表（一镜一行），
> 下游 `jimeng-drama-template.md` 产出 10 区块提示词。本文件管的是那个一直没人管的缝：
> **九列分镜表的镜头信息，怎么真正进到一个生成任务的提示词里。**
>
> **来源**：方法论参考社区项目 [jiayushi1-ux/script-to-shot-engine](https://github.com/jiayushi1-ux/script-to-shot-engine)
> v2.3.2（2026-10 拉取）。该仓库**未声明开源协议**（GitHub API `license: null`），因此本文件是
> **规则要点的自有表述 + 本项目适配改写，不是原文转载**；其中的数值阈值、硬格式、因果链结构属事实性
> 内容，已全部保留。标注「本项目」的条目是本仓库针对即梦画板链路的实测结论，非上游内容。
>
> **必读理由**：`jimeng-drama-template.md` 要求【画面内容】只写连续画面流、不写镜头编号；【镜头】又是
> 全片常量块。结果是**分镜表里逐镜的秒数 / 景别 / 机位，在提示词里丢失了**，全靠 Gemini4 自由发挥。
> 本文件补的就是这个洞。
>
> **与本技能的关系**：本文件**不替代** `video-director-prompt/references/jimeng-standard-template.md`
> （官方 5 模板，唯一真源）。逐镜头行格式落在 T1（`镜头N` 编号式）之内，时间戳写法落在 T2 的合法
> 秒数区间之内，**不引入第二套分段手段**。

## 一、先判断：这一段是动作还是对峙

两个模式互斥，按**本段实际内容**定性；同一场戏可以先文后武，逐段切换。

| | 动作模式 | 对峙模式 |
|---|---|---|
| **何时用** | 存在攻防、追逐、破坏、法术释放 | 由台词、视线、微动作（掐烟、合扇、按桌、离座）推进；全段无攻防，或攻防只在结尾作引爆点 |
| **因果链** | 局势与距离 → 发起 → 防守/闪避/命中 → 受力与位移 → 恢复或新局势 | 施压 → 承受 → 泄露或反制 → 新平衡 |
| **单镜时长** | 2–5 秒 | 2–5 秒（凝滞时刻可到 6 秒） |
| **台词** | 点缀 | **完整原句入镜，一句不跨镜** |

**判错的代价**：用动作模式写文戏 → 拍成一串无意义的正反问反打；用对峙模式写打戏 →
每镜都是「两人摆姿势」，动作因果断掉。

## 二、逐镜头行格式（本项目适配版）

一个生成任务（4–15 秒）内，把该任务对应的 2–4 个九列分镜行展开成**逐镜头行**：

```
镜头一（0-1.4秒）：光圈 f/4（中等景深，背景轻微虚化），焦段 35mm（全景），低角度（low angle）固定拍摄（static shot）；<动作发起 + 接触 + 结果>
镜头二（1.4-2.6秒）：光圈 f/2.8（浅景深，背景明显虚化），焦段 85mm（近景），手部近景（close-up detail）固定拍摄；<承接上一镜的局部变化 + 结果>
镜头三（2.6-4.0秒）：光圈 f/4（中等景深，背景轻微虚化），焦段 28mm（全景），侧后方中景（medium shot）手持（handheld）跟拍（tracking shot）；<局势变化 + 本任务收势>
```

### 2.1 每行六要素，缺一不可

1. **起止时间** `（起始-结束秒）`，写在镜头号后的括号里；
2. **光圈** `f/4`，值后紧跟中文景深描述，写 `光圈 f/4（中等景深，背景轻微虚化）`；
3. **焦段** `35mm`，值后紧跟中文景别描述，写 `焦段 35mm（全景）`；
4. **景别 / 角度 / 视角 / 固定或手持 / 运镜中至少两项**，专业术语按「中文（English）」；
5. **可见动作**；对峙镜头写完整台词原句（标情绪与语速）或微动作；
6. **接触 / 受力 / 位移，或对下一镜有用的结果**。

**不合格的镜头行**：
- 只写摄影参数、不写动作（`镜头一：光圈 f/2.8，焦段 85mm，固定拍摄。`）
- 只写「二人继续打斗」「继续缠斗」这类无信息动词
- 镜头行里写全片级风格与材质词（那是【风格】【布光锁定】的职责）

### 2.2 光圈 ↔ 景深、焦段 ↔ 景别对照（照抄，不要自创）

| 光圈 | 景深描述 |
|---|---|
| f/1.2–f/2 | 极浅景深，背景强烈虚化 |
| f/2.2–f/2.8 | 浅景深，背景明显虚化 |
| f/4–f/5.6 | 中等景深，背景轻微虚化 |
| f/8–f/11 | 深景深，前后景基本清晰 |
| f/16 以上 | 全景深，远近皆清晰 |

| 焦段 | 景别 |
|---|---|
| ≤24mm | 大全景 |
| 25–35mm | 全景 |
| 36–55mm | 中景 |
| 56–79mm | 中近景 |
| 80–120mm | 近景 |
| 121–200mm | 特写 |
| >200mm | 大特写 |

**按功能配参**：24–35mm + f/4 → 全身动作与空间位移；35–50mm + f/2.8–f/4 → 中景攻防；
80–100mm + f/2–f/2.8 → 表情、抓腕、锁颈；135–200mm + f/2.8–f/4 → 手、脚、武器接触细节
（狭小室内先确认拍摄距离，否则改近一档）。

**格式纪律**：写 `f/2.8` 不写 `f2.8`；写 `焦段 85mm（近景）` 不写「焦段85」；
括号内景深 / 景别注释**纯中文不附英文**（英文只给摄影描述正文，避免逐镜膨胀）；
同一术语在同一任务内只在**首次出现**时附英文，之后只写中文。

### 2.3 时间戳闭环（机械可校验，写完必查）

- 第一镜从 **0 秒**开始
- 后一镜起点 **等于** 前一镜终点（不得重叠、不得留空）
- 最后一镜**准确结束在该任务总时长**
- 小数最多 1 位，统一用**半角连字符** `-`；整数不补 `.0`

### 2.4 本项目硬约束：单任务 2–4 镜

> **这一条覆盖上游的镜头密度基准**，理由见文末「不采纳项 ①」。

| 任务时长 | 镜头数 | 单镜目标时长 |
|---|---|---|
| 4–6 秒 | 2 镜 | 2–3 秒 |
| 7–10 秒 | 2–3 镜 | 3–4 秒 |
| 11–15 秒 | 3–4 镜 | 3–5 秒 |

与 551 镜实测基准（平均 **4.2 秒/镜**、中位数 3 秒、76% 落在 1–5 秒）对齐。
**不要为了「信息丰富」硬塞 6 镜** —— 切点越多，AI 每次切镜都是一次概率性失败。

## 三、动作模式：因果链与观看重点

### 3.1 每个攻防单元走五段

```
局势与距离 → 发起动作 → 防守/闪避/命中 → 受力与位移 → 恢复或新局势
```

- 禁止只写「激战」「连续进攻」「高速缠斗」
- 禁止连续列互不产生结果的招式
- **动作之间必须有因果**：前一次格挡打开的空当、撞墙造成的失衡、被封死的退路、掉落的武器、
  被破坏的环境，要成为下一个动作的前提条件

### 3.2 动作单元 ≠ 镜头数

一个连续动作单元可以用多个镜头覆盖：镜头一看清冲拳与拍挡 / 镜头二近景抓腕 / 镜头三广角表现拉颈与位移 /
镜头四拍脚后跟滑停。**但抓腕、拉颈、搓步不得在每次切镜后重新发生一遍。**

增加镜头时优先拆「动作发起 / 接触点 / 脚步 / 受力 / 反应」这些**不同观看重点**，
不要为了加镜头而追加无因的新招式。

### 3.3 打击感五项（只写这五项）

1. 力量方向
2. 身体受力链与脚步变化
3. 武器震动、衣物或头发的跟随
4. **一个**环境次级反应
5. 短暂恢复或新的防御姿势

**镜头震动只用于决定性重击**，且写「轻微、短促」。不要每次命中都加慢动作、粒子和震动。

### 3.4 真人写实的额外要求

- 写重心、脚步和落点；写武器或拳脚的有效距离
- 受击后有短暂失衡与恢复；体力下降要体现为动作幅度变化
- 防守动作要**可读**，不是双方无接触地挥舞
- 避免：无依据腾空、连续空翻、瞬间改变方向、挨重击后毫无反应、摄影机比人物移动更剧烈

### 3.5 一对多（短剧常见）

- 同一时刻**最多 1–2 名**对手完成精确前景交互
- 其余对手分配：封路 / 接近 / 补位 / 倒地 / 扶起同伴 / 形成武器威胁
- 一个敌人倒下后，说明他**仍在空间中的位置**（不必每个阶段重复所有人）
- 主角的移动路线必须解释「为什么没有被同时包住」

## 四、对峙模式：文戏的镜头规范

> 短剧里文戏占比最高，但本技能此前**完全没有**这一层。这是本文件最该被用到的部分。

### 4.1 张力因果链

```
施压（台词或动作发起）→ 承受（听方微反应）→ 泄露或反制（视线回避、手部失控、打断、离座）→ 新平衡
```

**每个张力单元必须有人失态或关系改变**。不允许「说完换下一个人说」的流水对白。

内部的三个问题（不输出）：角色此刻要什么 / 最大限制是什么（对峙里通常是**信息差、把柄、空间权力**）/
本段结束时什么必须改变。

### 4.2 台词-镜头三条硬规则

1. **一句完整台词不跨两个镜头**
2. 长台词（>4 秒）给一个连续镜头，用缓慢推进维持画面活性
3. 听方反应镜头**不重复台词**，只写反应本身

**写法**：动作描述里写完整原句并标情绪与语速：

```
镜头二（1.4-3.6秒）：光圈 f/2.8（浅景深，背景明显虚化），焦段 85mm（近景），面部近景（close-up）缓慢推进（push in）；他（慢，一字一句）：「船畀人劫，係一把刀。堂口畀人抽水，係第二把。」
```

**方言保留原文**，不改写为书面语。
**口型时长**：中文对白约 **4–5 字/秒**，按字数核对镜头时长；不够就延长本镜或调整分配，
**绝不删台词**。

### 4.3 镜头功能配额（按本项目 2–4 镜口径压缩）

上游原口径是「每 15 秒 / 合计 ≤9 镜」：建立空间 ≤1、说话人 ≤3、听方反应 ≤2、微动作特写 ≤2、
局势变化 1。本项目单任务只有 2–4 镜，按比例压成：

| 任务时长 | 建立空间 | 说话人 | 听方反应 | 微动作特写 | 局势变化 |
|---|---|---|---|---|---|
| 4–9 秒（2–3 镜） | ≤1 | 1–2 | ≤1 | 0–1 | 0–1 |
| 10–15 秒（3–4 镜） | ≤1 | ≤2 | ≤1 | ≤1 | 1 |

- 反应镜头**不连续超过两个**
- 不重复拍同一角色的同一反应
- **不为凑镜头数切分台词，不为凑镜头数重复微动作**

### 4.4 微动作反馈四类（一个特写只承载一个）

| 类别 | 可写 |
|---|---|
| 手部失控 | 掐烟、折扇停住、指节泛白、手离开扶手悬空 |
| 坐姿变化 | 上身前倾、将起未起、慢慢坐回 |
| 持物变化 | 放下、推开、合拢、不触碰 |
| 视线变化 | 抬眼、移开、第一次看向某人 |

### 4.5 多人同框

- 每个镜头除焦点人物外，**用一句交代背景**：「其余人保持原位静止」或具体微动作（「七叔摇扇未停」）
- 群体同步反应（全场静下来、众人变色）用**一个全景或双人中景**整体呈现，不拆成逐人反应
- **视线是主要动作资源**：写明谁看谁、谁先移开；视线变化就是张力单元的受力结果
- **空间权力**写进站位：谁站着、谁坐着、谁正对门、谁背对门，并保持连续

### 4.6 收尾

- 字幕卡：写入最近镜头的动作描述末尾，「画面叠字幕：×××」
- 黑屏 / 渐隐：写入结尾状态，「画面随××渐黑」
- **剧本未要求时不主动加**字幕卡与转场（与【限定】「禁止加文字和标注」一致）

## 五、连续拆段（多任务长戏）

> 本技能是按任务批量生成的，天然要拆段。拆错位置 = 观众看出断裂。

### 5.1 优先在这些节点结束一个任务

- 一次攻防已经产生明确结果
- 人物到达新的空间区域
- 武器完成夺取、丢失、断裂或更换
- 一方完成脱困、压制或优势反转
- 门、墙、烟尘、掠过前景等**自然遮挡**提供衔接点

### 5.2 **绝不**在这些状态中间结束

- 攻击已发起但尚未命中或避开
- 抓抱、夺取武器或换弹还没完成
- 人物仍在半空且落点不明
- 法术或爆炸已释放但结果尚未出现

### 5.3 跨任务只追踪 6 项状态

1. 人物所在区域与大致面向
2. 武器由谁持有、哪只手
3. 持续伤势 / 服装 / 武器变化
4. 关键敌人的局部状态
5. 已发生的场景破坏
6. 下一段摄影机从哪一侧继续

**不生成**完整坐标、全量状态 JSON、角色逐帧位置表——那是负担，不是连续性。

### 5.4 交接写法

承接信息**不单独成行**，直接写进下一段【故事背景】或【画面内容】的开头：

```
【故事背景】承接上一段，他仍半跪在楼梯第二阶，右手单刀未松；对手停在低两级处。
```

下一段必须从上一段结尾状态的**事实**开始，但可以改写句式。**不要把上一段提示词整段复制到下一段。**

## 六、集中约束段

10 区块里的【一致性】+【限定】承担这个职责。本文件补充三条容易漏的：

1. **至少 3 项必须引用本段的具体事实**（人名、持物、座位、血迹、已熄灭的灯），
   不允许整段由「人物穿模、动作瞬移、无音乐无字幕」这类通用项组成
2. **项数控制在 5–8 条**。上游规则写 5–8，但它自己的示例实际写了 13–18 个约束点——
   那是**反例**，不是标准。约束越长，模型越容易只执行最后一句
3. **声音要求固定放最后一项**

```
【一致性】<保持>: 两人持握关系、画面左右、熄灭的灯笼不复亮；<避免>: 武器换手、同一动作切镜后重演、穿模；<保留>: 脚步、喘息、兵器碰撞；无音乐，无字幕。
```

## 七、素材绑定纪律（本项目实测，最容易踩）

> 实测于本仓库 `project-core.ts` / `video-pipeline.ts`，结论直接用。

### 7.1 `@资产名` 不是素材绑定

上游用 `@资产名（特征）` 作锚点。在本仓库里：

- `@角色名` **不会被拒绝**，但也**不构成素材绑定** —— `classifyVideoPromptCompleteness` 会判
  `incomplete`（缺少 `图片N` 绑定），而 `normalizeReferenceLabels` 也不会去改它（正则只认
  `@图片N` / `@Image N` 这类带编号形态）。**最危险的是静默通过：以为绑了，其实没绑。**
- 所以：`@资产名` 只能当**文字称谓**用，真正的绑定仍然是裸标签 **`图片N`**

```
✅ 图片1（斗笠、深蓝短打、右手单刀）为刀客   ← 绑定 + 锚点，两个都在
❌ @刀客（斗笠、深蓝短打、右手单刀）         ← 只有锚点，没有绑定
```

### 7.2 素材文件名不能出现在提示词里

`validatePromptContent` 会把**素材文件名 stem（≥3 字符、非纯数字）**判为泄漏并**拒绝**。实测：

- 素材叫 `刀客甲.png`，提示词里写「刀客甲」→ `prompt leaks internal material filename or alias: 刀客甲`
- 素材叫 `char_01.png` → 通过

**两条规避**（任选其一，建议都做）：
1. 素材文件用**无语义名**（`char_01.png`、`scene_pool.png`），角色名只活在提示词和资产卡里
2. 若素材必须按角色名命名，提示词里的称谓要**避开文件名 stem**（素材 `刀客甲.png` → 提示词用「刀客」而非「刀客甲」）

### 7.3 其余既有纪律不变（附实测后果）

- 只用裸标签 `图片N` / `视频N` / `音频N`；**不主动写** `@图片1`、`参考图片1`、`@Image 1`
- **「参考图片N」也会被判非规范**（实测）：`爸爸参考图片1` → completeness 判 `incomplete`
  （「素材引用必须使用中文裸标签…禁用 @图片N、参考图片N、@Image N 等变体」）；
  改成裸标签形态立刻通过：

  ```
  ❌ 爸爸参考图片1，场景参考图片2      → incomplete
  ✅ 图片1为爸爸，图片2为场景          → complete
  ```

  注：`normalizeReferenceLabels` 在提交前会把 `参考图片1` 改写成 `图片1`，所以**不会导致付费失败**，
  但会让完整性分类误判、多走一轮语料检索。**新写的提示词一律用裸标签形态。**
- 同一素材全片同号；每段**整体**至少含一个 `图片N`
- 素材编号按 **图片 → 视频 → 音频** 的传入顺序重编，不按素材库文件名
- 不残留 `.png` / `.mp4` 等扩展名

## 八、与 10 区块的接口（怎么拼进去）

**唯一改动点：把【镜头】从「全片常量块」升级为「本段逐镜头表」。**

| 区块 | 变化 | 说明 |
|---|---|---|
| 【风格】【布光锁定】【参考】【设定】【特殊要求】【导演】【一致性】【限定】 | **不变** | 保持每段逐字复用，这是跨段视觉统一的依据（见文末不采纳项 ②） |
| 【故事背景】 | 不变 | 一句话；连续拆段时以「承接上一段，」起句 |
| 【画面内容】 | **不变** | 仍是连续动作流 + 台词流，**不写镜头编号**（B2 规则） |
| **【镜头】** | **改** | ① 先写一句全片机位策略（原常量内容）② 另起「分镜：」逐镜行 |

拼装后的样子：

```
【镜头】稳定机位与极缓慢推轨，自然切镜，最远到中景，优先拍反应与侧影。
分镜：
镜头一（0-1.4秒）：光圈 f/4（中等景深，背景轻微虚化），焦段 35mm（全景），低角度（low angle）固定拍摄（static shot）；爸爸从右侧入水，肩背发力，水花在肩侧翻起。
镜头二（1.4-3.0秒）：光圈 f/2.8（浅景深，背景明显虚化），焦段 85mm（近景），侧后方近景（close-up）缓慢跟拍（tracking shot）；水面光斑晃动，他侧头看向画外，笑了一下。
```

**这样【画面内容】和【镜头】不打架**：前者管「这场戏怎么演」，后者管「怎么拍」，
逐镜信息不再丢失。

## 九、字数预算

| 任务时长 | 逐镜头部分目标 |
|---|---|
| 4–6 秒（2 镜） | 150–350 字 |
| 7–10 秒（2–3 镜） | 300–550 字 |
| 11–15 秒（3–4 镜） | 500–900 字 |

**超长时的裁剪顺序**（从右往左删，不硬砍每镜）：

```
风格锁定 > 空间站位 > 动作连续性 > 接触与受力 > 台词原句 > 镜头功能 > 参数 > 结尾状态 > 必要约束 > 装饰性光影
```

**允许且必要的重复**：每一镜都写光圈与焦段（这是格式的一部分，不是为了凑字）。
**禁止的重复**：把【布光锁定】【一致性】的文字塞进镜头行；同一术语英文标注两次；
同一机位声明反复写。

## 十、不采纳项（上游与本项目冲突，以本项目为准）

### ① 15 秒 ≥10 镜（动作）/ ≥5 镜（对峙）—— **不采纳**

上游实测示例：动作模式 12 镜/15 秒、单镜均 1.25 秒；10 镜/15 秒、单镜均 1.52 秒；
对峙 6.5 镜/15 秒。本项目的结论相反：

- `production-pipeline.md` B1：**单任务 2–4 个切点明确的镜头**，「7–15 秒内做多景别 + 多人走位，生成模型必崩」
- 551 镜实测：平均 **4.2 秒/镜**

即梦就是 Seedance，**同一个模型上的两种相反经验**。上游的立场是「镜头数服务动作、一镜一个观看重点」，
理论上成立；但 1.25–1.5 秒/镜意味着 15 秒内 10 个切点，每个切点都是一次概率性失败。
**先按本项目的 2–4 镜做，别整套照搬。** 确实要试高密度，用**单个任务**做 A/B，不要全片铺开。

### ② 全局风格锁定只写一次、Clip 内不得重复 —— **不采纳**

上游的理由是「防止每段重复膨胀」。但本项目是**每段独立提交到画板节点**，模型看不到别的段——
不复制【布光锁定】就等于丢风格。上游自己在 continuous-mode 里也承认「每个 Clip 仍须独立可投喂」。
**保持每段逐字复制。** 可以借的只有一点：Clip 标题里带一句风格名（本项目已有【风格】）。

### ③ 15 秒正文 1000–2000 汉字 —— **不采纳（口径不同）**

上游的正文**全部**是逐镜头有效信息；本项目的 400–900 字/段里有约 40% 是【布光锁定】【一致性】【限定】
这类常量块，真正新写的只有【参考】+【画面内容】+【镜头】。**字数不是目标，信息密度才是。**
按第九节的分任务预算控制即可。

### ④ 可以借但要注意的两处坑

- 上游示例里出现过 `短暂500fps升格（slow motion）` —— **fps 是本仓库明令禁止的写法**（会进提交文本）。
  升格只写「升格（slow motion）」，不写数值
- 上游 Clip 标题用全角「｜」拼接（`### Clip 01｜15秒｜16:9｜风格`）。它是 Markdown 标题、在代码块外，
  本身不违规；但**如果整份 md 当提示词提交就会触发管道符拒绝**。本项目只提交区块正文，标题不进提交文本
