# 脚本大纲 → 即梦提示词：短剧制片方法论

> **一句话**：把一段自由文本脚本大纲，经过**四次确定性变形**，变成 N 段可直接粘进即梦画布的 11 区块提示词。
>
> 本文档的每一条规则都来自真实交付项目（建发·观澜「周末听谁的」「家越住越大」129 户型篇、狮山金茂府「24H 金质生活」、观澜园林篇），
> 并标注了出处与失败代价。**没有一条是凭想象写的。**

---

## 速览：如果只记 10 条

1. **四段流水线**：脚本大纲 → 导演脚本（九列分镜表）→ 执行脚本（台词→场景卡映射 + 任务划分）→ 即梦提示词（11 区块 × N 段）
2. **想和记分开**：Agent 管确定性结构（分镜/时长/台词/素材/校验），LLM 只管创意正文（画面/镜头/故事背景/布光）
3. **九列分镜表唯一格式**：`镜号|时长|摄影角度|景别|画面内容|场景|声音|备注|叙事目的`，一个镜头一行，每镜只装一个信息
4. **时长是算出来的**：台词字数 ÷ 4.5 字/秒 + 动作镜头；**永远推翻脚本自带的时间标注**
5. **执行脚本里那张「台词→场景卡」映射表是防错闸门**，做完才能写提示词；写完还要反向再查一遍
6. **11 区块 = 7 个常量块 + 4 个变量块**；常量块全片逐字相同（提取成「通用提示词包」），变量块每段重写
7. **正文只写角色名，不写「图片N」**；`图片N` 只出现在【参考】块。上画布只改【参考】块
8. **每段 2400–3300 字、2–4 镜、4–15 秒**；这是跨项目恒定值，不由段长决定
9. **不写负面词、不写字幕、不写 BGM、不写小数秒、不写文件名**；负面词会被反向诱导
10. **单段合格 ≠ 整片合格**。必须有「整片叙事 + 衔接设计」这一层，否则就是片段拼凑

---


## 0. 这份方法论要解决什么

三个真实项目暴露出同一个结构性矛盾：

| 矛盾 | 表现 | 根因 |
|---|---|---|
| **创意要自由，但事实不能错** | 提示词读起来很顺，画面却和台词对不上（说学校给了小区大门图） | 同一个模型同时负责「想画面」和「记事实」，事实被创意挤掉 |
| **结构要稳定，但内容要变化** | 9 段提示词里【布光锁定】只写一次，后面 8 段风格漂移 | 没有区分**常量块**与**变量块** |
| **要快，但返工更慢** | 一个 90 秒片子逐段微调 81 轮（真实记录） | 上游没锁死，下游只能反复改 |

**解法**：把「想」和「记」彻底分开——

- **Agent / 脚本负责确定性结构**：任务划分、时长、镜数、台词逐字、素材绑定、常量块拼装、机械校验
- **LLM 只负责创意正文**：画面内容、镜头运动、故事背景、布光描述
- **机械校验负责兜底**：凡是能写成正则/阈值的规则，绝不靠人眼

这条分界线是整份方法论的地基。**越界的两种表现都是病**：Agent 手写创意正文 → 模板腔；LLM 决定镜数与时长 → 结构失控。

## 1. 四阶段总览

```
① 脚本大纲          ② 导演脚本            ③ 执行脚本            ④ 即梦提示词脚本
   客户原文      →   导演定调+九列分镜  →  台词映射+任务划分  →  11 区块 × N 段
   (docx/md)         00-导演骨架.md        01-执行脚本.md        02-即梦提示词.md
      ↓                    ↓                    ↓                     ↓
   事实提取           视听决策             生产排程              可直接提交
```

| 阶段 | 产物 | 这一阶段唯一要回答的问题 | 谁做 | 通过标准 |
|---|---|---|---|---|
| ① 脚本大纲 | 母本 docx / md | **卖点与台词有哪些？信息点是否齐全？** | 客户 + Agent 诊断 | 信息点清单 100% 可逐条核对 |
| ② 导演脚本 | `00-导演骨架.md` | **这个片子长什么样？（定调、节奏、每一镜拍什么）** | Agent 搭骨架 → LLM 写创意 | 九列表每镜一信息 + 12 项自检通过 |
| ③ 执行脚本 | `01-执行脚本-正式版.md` | **怎么分任务？哪句台词用哪张图？** | Agent（+LLM 辅助） | 台词→素材映射逐句成立 + 素材数核对 |
| ④ 即梦提示词 | `02-即梦提示词-可提交版.md` | **每段给模型的字面指令是什么？** | LLM 写变量块 + Agent 拼常量块 | 11 区块齐全 + 每段 2400–3000 字 + 机械校验通过 |

**为什么必须四段，不能压成两段**：

- ② 与 ③ 混在一起 → 分镜时想「素材够不够」，会为了迁就素材而改戏（真实发生：为了用上 18 张场景卡，硬塞进不存在的空间）
- ③ 与 ④ 混在一起 → 提示词里出现素材编号，画布一换节点就要全文重排（真实发生：v1/v2 版提示词正文写「图片1」，换素材后整段失效）

## 2. 阶段①：脚本大纲（输入契约）

**你只需要给我这些，剩下的我来做。**

### 2.1 最小可用输入

| 字段 | 必要性 | 说明 |
|---|---|---|
| 脚本正文 | **必需** | docx / md / 纯文本均可。有场景划分更好，没有也行 |
| 时长目标 | **必需** | 「60 秒」「90 秒内」；**若脚本自带时间标注，一律忽略并推翻**（历次实测：自带时间几乎必然与台词量不匹配） |
| 台词归属 | 强烈建议 | 哪句是谁说的。缺失时按上下文推定并标注 |
| 素材现状 | 强烈建议 | 是否已有场景卡/角色卡/音色；没有则先走素材生成 |
| 卖点/信息点 | 若客户有 | 房地产类必须给，否则无法做「信息零丢失」核对 |
| 禁止项 | 视项目 | 不要字幕 / 不出现路人 / 不出现楼梯……这些会直接进【限定】与【特殊要求】 |

### 2.2 第一步永远是「诊断」，不是「改写」

对客户原文先做四类诊断（真实项目里这四类问题**全部出现过**）：

| 诊断项 | 典型症状 | 处理原则 |
|---|---|---|
| **时长/台词量不匹配** | 55 秒塞了 15 句长台词 | 时长是**核算输出**，不是约束。先算台词需要多少秒，再定时长 |
| **台词书面化** | 「这约16㎡入户电梯厅真宽敞，可以做成收纳间，你的露营装备、我的包包、孩子的滑板车都可以放这里」 | 口语化，但**信息点一个不许丢** |
| **逻辑/常识硬伤** | 洋房写成「下楼梯」被画成一楼带院；「走楼梯」但素材没有楼梯 | **优先动画面，不动台词**（理由见 §2.4） |
| **术语/品牌口径** | 面积、地铁距离、学校全称写错 | 以客户资料为准，不自行修正 |

### 2.3 台词自然化：用户三次驳回换来的方法

这是整个方法论里**返工最多**的一步（真实对话记录：连续 6 轮被驳回）。三次迭代的结论：

| 版本 | 做法 | 用户判定 | 为什么不行 |
|---|---|---|---|
| v1 | 让 Gemini 自由润色 | ❌「改得有些多了」 | 过度修改，原意丢失 |
| v2 | 强调「最小干预，只许四类改动」 | ❌「现在有些太拘谨了」 | 改得太保守，机械感没解决 |
| **v3** | **信息点清单法** | ✅ 通过 | 见下 |

**v3 信息点清单法（采纳）**：

1. 把原文逐句拆成**信息点**（一句台词通常 2–4 个信息点），列成清单
2. 让 LLM 重写台词，**只约束「信息点必须全在」，不约束用词**
3. 重写后**逐条核对 53 条信息点**（真实项目做到 53/53 全在）

> **一句话规则**：把「尊重原句」换成「尊重信息点」。句子的壳可以换，核不能丢。

**两轮法（比一次到位稳）**：

```
第 1 轮：只求自然，放开写（一定会写胖，台词变长）
第 2 轮：只做瘦身，只删水、不删信息（去掉语气赘词、合并同义句）
```

自然度和长度是**两件事**，同时约束会两头不到岸。

**给 LLM 的措辞模板**：

```
下面是台词的信息点清单（N 条）与字数配额（X 字 ± 10%）。
请把这些信息点全部保留，用口语重写；不要求保留原句措辞。
改写后我会逐条核对信息点，缺一条即不合格。
```

> 反例：`请让台词更自然一些` —— 模型会自由发挥，信息大量丢失。
> 正例：`信息点清单 + 字数配额 + 逐条核对承诺` —— 实测做到 53/53 信息点零丢失。

### 2.4 「优先动画面，不动台词」的理由

台词是客户/法务/销售确认过的，改台词 = 重新走确认流程。
画面是执行层，改了不影响任何人签字。

所以遇到「逻辑硬伤」，顺序是：

```
先改画面表达（换景别、换机位、换动作、换成特写）
  ↓ 还不行
再改镜头结构（拆镜、并镜、换场景）
  ↓ 最后才
动台词，且必须标注改了哪个信息点
```

真实案例：台词说「我跑下去比你们快」，但素材里没有楼梯。
**解法不是改台词，是改画面**：孩子朝镜头跑来、冲出画面。不给楼梯、不给门、不给轿厢——观众自己脑补了「跑下去」，逻辑成立，台词一字未动。

## 3. 阶段②：导演脚本（00-导演骨架.md）

### 3.1 章节结构

**5 个核心章（必填）+ 3 个可选章**：

| 章节 | 内容 | 必填？ |
|---|---|---|
| 〇、本版改了什么 | 相对上一版的差异（4 列表） | 仅修订版 |
| 一、导演定调 | 六维判断 + 七项视听决策 + 意象体系 | ✅ |
| 二、节奏规划 | 双轨节奏 + 镜头组划分 + 节奏诊断（7 列表） | ✅ |
| 三、时长与台词核对 | 台词字数 × 分场核算 + 结论（5 列表） | 需要核时长时 |
| 四、九列分镜表 | **每镜一行，见 §3.2** | ✅ |
| 五、生成任务划分 | 任务 / 镜数 / 时长 / 场景 / 素材数（6 列表 + 合计） | ✅ |
| 六、12 项逻辑自检 | 见 §7.1 | ✅ |
| 七、下一步输入 | 交给 LLM / 下一阶段的输入清单 | 建议 |

> 两种真实形态：**首版骨架**（一/二/四/五/六）与**修订骨架**（加〇和三）。
> 129 户型篇是首版 5 章；《周末听谁的》v2 是修订版 8 章，因为它要论证「为什么值得重跑」。

### 3.2 九列分镜表（唯一权威格式）

**列头逐字如下，顺序不可变**：

```
| 镜号 | 时长 | 摄影角度 | 景别 | 画面内容 | 场景 | 声音 | 备注 | 叙事目的 |
```

真实实例（狮山金茂府，30 镜 / 120 秒）：

```
| 1 | 00:00-00:04 | 平视 | 特写 | 女主躺在米色软包床的被褥上，睫毛轻动后缓缓睁眼，晨光从左侧纱帘落她脸上 | SC01 主卧 | 极轻的呼吸声、织物摩擦 | 固定 | 交代这个人是怎么醒来的——用"睁眼"这个最小动作进入她的一天 |
| 2 | 00:04-00:08 | 平视 | 特写 | 右手食指按下香槟金边框的黑色触控屏，屏幕亮起温湿度数字 | SC02 五衡面板 | 触控屏滴声 | 固定，浅景深 | 把"科技呵护"落成一个可读的数字，全片第 1 次产品证据 |
```

**三条铁律**：

1. **一个镜头一行**：硬切/叠化/跳切算新镜号；推拉摇移、焦点转换、角色进出画**不算**
2. **每镜只装一个可见信息**：不再有「4 秒内起床+走路+按面板+拉帘」这种多层压缩
3. **叙事目的不直接进提示词**，但它决定了这一镜该用什么景别与机位

### 3.3 时长基准（551 镜实测）

| 信息密度 | 时长 |
|---|---|
| 单一信息 | 2–3 秒 |
| 双重信息 | 4–5 秒 |
| 多层信息 | 6–8 秒 |
| 升华/定版 | 6–10 秒 |

**核心公式（实测闭合，可直接当预算器）**：

```
总时长 = 台词汉字数 ÷ 4.5 + 无台词镜占用秒数

《周末听谁的》实算：207 ÷ 4.5 + 19.5 = 46.0 + 19.5 = 65.5 秒
                     与 27 镜逐镜时长之和完全相等 ✅
```

那 19.5 秒的物理构成（不是拍脑袋）：

| 项 | 秒数 |
|---|---|
| 7 个纯无台词镜 | 14.0 |
| 20 个台词镜的放慢余量（说话时要给动作留时间） | 5.5 |

**修正系数**：台词镜内实测 **4.02 字/秒**，比 4.5 的预算**慢 11%**。
所以 4.5 是"预算上限"，真实语速约 4.0–4.3 字/秒。核算紧张时按 **4.2** 更安全。

**台词与镜头的分配**：

```
25 句台词 → 20 个台词镜（一句台词不跨镜）
          其中 5 个镜各装 2 句
剩下 7 个纯无台词镜（空镜/情绪留白/特写）
```

> **「一句台词不跨镜」**：同一句台词不能拆到两个镜头里说。声音会断，口型对不上。
>
> **九列表的「时长」列是「全片累计时码」**（如 `00:48.0-00:50.8`），
> 到提示词阶段才改成「每段 0 起、首尾相接的闭环」（如 `0-2.8 / 2.8-4.0`）。
> 两个阶段的口径不同，转换时最容易出错。

### 3.4 镜头组四类（决定节奏形状）

| 类型 | 作用 | 用在 |
|---|---|---|
| 递进组 | 信息逐层加深 | 开场建立、结尾回环 |
| 因果组 | A 动作引发 B 反应 | 人物戏、对话戏 |
| 蒙太奇组 | 并列铺陈，压缩时空 | 资源/地标掠影、卖点罗列 |
| 对比组 | 两两并置产生意义 | 守护 vs 安睡、室内 vs 室外 |

真实配比（狮山 30 镜）：递进组(2) → 因果组(4) → 蒙太奇组(10) → 递进组回环(11) → 对比组(3)。
剪辑节奏配比：**人物动作段 4 秒/镜（60%）/ 地标段 3.5–4.5 秒/镜（30%）/ 定版升华 6 秒（10%）**。

## 4. 阶段③：执行脚本（01-执行脚本-正式版.md）

> **这一阶段是整个流水线的「防错配闸门」。** 三个项目里最严重的返工全部发生在这里被跳过的时候。

### 4.1 六个章节（顺序固定）

| 章节 | 内容 | 作用 |
|---|---|---|
| 一、剧本定稿 | 场次 / 角色 / 台词 三列表，逐句锁定 | 台词进入不可变状态 |
| **二、台词 → 场景卡映射** | 台词关键句 / 对应场景卡 / 所在任务 | **核心防错机制** |
| 三、分镜表 | 见 §4.2（**6 列，不是 9 列**） | 把导演视角转成生产视角 |
| 四、任务划分 | 任务 / 镜 / 时长 / 场景 / 素材数 + 合计 | 决定产出几段提示词、每段绑几张图 |
| 五、执行备注 | 本项目专属修正项清单 | 把历史教训固化成约束 |
| 六、参考图使用清单 | 文件 / 用于任务 | 素材与任务的对应表 |

### 4.2 九列 → 六列的压缩规则

**九列表 ≠ 执行脚本的表**。执行脚本按生产需要重排成 6 列：

```
| 镜 | 时长 | 场景卡 | 台词 | 画面要点 | 任务 |
```

压缩映射：

| 九列 | 六列 | 说明 |
|---|---|---|
| 镜号 | 镜 | 原样 |
| 时长 | 时长 | 原样 |
| 场景 | **场景卡** | 从文字场景名 → 具体素材文件编号（SC01/SC02…） |
| 画面内容 | **画面要点** | 收敛成一句话，保留「谁在哪、做什么」 |
| 摄影角度 / 景别 / 备注(运镜) | — | **暂时收起**，留给阶段④由 LLM 展开成逐镜行 |
| 声音 | 台词 | 只保留台词；环境声交给【设定】常量块 |
| 叙事目的 | — | 不进执行脚本，它是导演判断依据 |
| — | **任务** | 新增：这一镜归属哪个生成任务 |

**为什么收起摄影语言又要在阶段④展开**：九列表里「平视/特写/固定」是**决策**，阶段④要写的是「f/2.0、50mm、平视固定机位、static shot」——同一件事的两种粒度。中间隔一层，是为了让 LLM 在写的时候有自由度，同时不丢决策。

### 4.3 台词 → 场景卡映射：为什么这是最重要的表

真实事故（129 户型篇 v1/v2）：T07 的正文写「拎购物袋走到小区大门」，但绑定的素材是**学校图**。模型拿到学校图，正文说大门——于是画出了不存在的地方。整段作废重跑。

**根因**：分镜时按「戏」排，绑定素材时按「图」找，中间没有核对。

**解法**：在写提示词**之前**，先把每一句台词钉到具体素材上：

```
| 台词关键句 | 对应场景卡 | 所在任务 |
| 这入户电梯厅约16平 / 收纳间 | 入户电梯厅（SC02） | T02 |
| 四开间朝南 / 四房布局 | 四开间朝南（SC05） | T03 |
| 地铁1号线金枫路站 200米 | 地铁站正对站口（SC12B） | T06 |
```

做这张表时，三类错误会立刻暴露：

1. **说了但没图**（台词说学校，素材里没有学校）→ 补素材或改画面
2. **有图但没用**（准备了 18 张场景卡，只用了 6 张）→ 检查是不是漏了卖点
3. **图文错位**（同一段里说 A 拍 B）→ 拆任务或换图

> **规则**：这张表没做完，不许写提示词。写完提示词后还要**反向再查一遍**：这段正文提到的每个空间/道具，是否都在本段素材绑定里？

### 4.4 任务划分的三条约束

| 约束 | 数值 | 来源 |
|---|---|---|
| 单任务时长 | 4–15 秒（模型上限 15 秒） | Seedance 2.0 系列硬限制 |
| 单任务镜数 | **2–4 镜** | 实测：超过 4 镜模型开始丢镜 |
| 单段提示词字数 | **2400–3000 字** | 实测三个项目均值 2458 / 2611 / 2917；硬上限 4000 字 |

> **镜数 vs 字数**：2 镜约 2400–2600 字，4 镜约 2900–3250 字。换言之**每镜约 600–700 字**。
> 写超了就是废话，写少了就是信息不足。

### 4.5 分块规则：哪些镜头可以放进同一段

**用户原话（2026-10-31，狮山项目）**：

> 「你写即梦 AI 执行脚本前，还需要对我们的镜头进行分块，把可以一起生成的镜头放到一起
> （比如会使用同样的或者有很多图共用的连续镜头，实际上可以作为一段）。
> 同时因为即梦 AI 有最短 4 秒限制，你也需要进行规范优化。」

成段的三个条件（**满足任一即可合段，但必须同时满足"连续"**）：

| 条件 | 说明 |
|---|---|
| **素材共用** | 相邻镜头用同一组参考图（同一个空间、同一批人物） |
| **时空连续** | 同一场景同一时刻，中间没有跨越 |
| **叙事单元完整** | 这几个镜头合起来表达一个完整的动作或意思 |

**不该合段的情况**：

- 换了场景 / 换了时间（即使素材共用）
- 中间有硬切转场（叠化、黑场、快切）
- 合起来超过 15 秒（模型上限）

**4 秒下限规范化**（易漏）：

```
即梦最短生成 4 秒。
若某段算出来只有 2–3 秒 → 生成时仍填 4 秒，多出的时间给动作留白。
若某镜只有 1 秒 → 必须与相邻镜合段，否则无法单独生成。
```

真实实例：狮山 T15 定版「成片 3 秒 / 生成 4 秒」——**成片时长与生成时长可以不同，生成不能低于 4 秒**。

## 5. 阶段④：即梦提示词脚本（02-即梦提示词-可提交版.md）

### 5.1 11 区块，顺序不可变

```
【风格】【布光锁定】【参考】【设定】【特殊要求】【导演】【故事背景】【画面内容】【镜头】【一致性】【限定】
```

### 5.2 常量块 vs 变量块（这是全套方法论最省力的一个设计）

| 类别 | 区块 | 谁产出 | 规则 |
|---|---|---|---|
| **真常量（4 块）** | 风格 / 布光锁定 / 导演 / 限定 | Agent 拼装 | **全片逐字相同**，实测 md5 全同 |
| **参数化常量（3 块）** | 特殊要求 / 设定 / 一致性 | Agent 按段落类型填参数 | 结构相同，参数随段落类型变 |
| **变量（4 块）** | 参考 / 故事背景 / 画面内容 / 镜头 | LLM 写创意，Agent 补事实 | 每段独立 |

**参数化常量的真实参数**（实测）：

| 区块 | 参数维度 | 实例 |
|---|---|---|
| 【特殊要求】 | 空间类型 | 室内 18 字符 / 空镜 27 字符 / 户外 48 字符（三段模板按需选） |
| 【设定】 | 有无台词 | 有台词：「人物说标准普通话，自然有情绪」；无台词：「仅保留环境声与物理音效」 |
| 【一致性】 | 段落内容 | 基础段全同 + 尾句追加本段专属约束（如「妈妈挎包已挎在左肩」） |

**产出方三分（实测，可作验收基准）**：

| 生产者 | 占比 | 内容 |
|---|---|---|
| 机拼常量 | **52.5%** | 【布光锁定】1524 字符 × 9 段 = 13716 / 全文 26137 |
| LLM 创意 | **29.1%** | 【故事背景】+【画面内容】+【镜头】策略句 |
| Agent 搬事实 | **18.5%** | 【参考】+【设定】+【特殊要求】+【一致性】 |

> **这个比例解释了「为什么每段字数恒定」**：一半以上是常量。
> 也解释了「为什么改一段只要 5 分钟、重写整片要 40 分钟」——真正要重想的只有 29%。

> **常量块必须逐字复制——但「必须」和「实际」之间有 8% 的缝。**
>
> 实测（《周末听谁的》v2）：把 Agent 拼装版与 LLM 生产版按「段 × 区块」逐字比较，
> **63 个非创意块实例里有 5 个不同，复用率只有 92.1%**：
>
> | 段 | 区块 | 漂移 |
> |---|---|---|
> | T03 | 【导演】 | 「商业生活方式」→「商业**地产**生活方式」 |
> | T05 | 【特殊要求】 | 「瑜伽**段**」→「瑜伽**造型**」 |
> | T06a | 【设定】 | 「笑声与球声」→「笑声与**乒乓**球声」 |
> | T06b / T06c | 【一致性】 | 「隔**网**面对面」→「隔**台**面对面」（**改变了物理设定**） |
>
> 而且这 5 处**在人工审阅稿的自查表里都没被记录**——靠人眼看是漏掉的。
>
> **所以验收必须加一条机械 diff**：把「常量块基准版」与「待提交版」按区块逐字比较，不一致就回填。
> 一致性契约一旦破坏，就没法再用字符串比较做自动校验了。

通用提示词包实例（可整段复用，狮山金茂府实战版）：

```markdown
## 【风格】
现代东方雅致建筑美学与暖白低饱和生活方式电影风格，超写实。

## 【布光锁定】

and Kore-eda's domestic observation. Shot on a clean digital 35mm full-frame sensor with
medium-shallow depth of field, zero grain, zero halation, zero soft-focus bloom. [...8 维度全文...]

二、公共空间（园林、会所、大堂、小学、街道、场馆、商圈、地铁）：允许1至3位住户作中后景虚化

标志物相对位置不变；同一任务内光源方向不跳变；禁止字幕、禁止新增文字与标识。
1. 场景内既有文字是场景特征，保持原样，不新增、不改写、不抹除；
2. 一家人同框时身高比例为 男主:女主:男孩 = 1 : 0.92 : 0.67；
3. 女主固定为黑中长发低马尾、金色椭圆小圈耳环、豆沙粉唇；男主不戴眼镜、左手腕戴表；
   男孩左颊颧骨下方有一颗小痣。

## 【限定】
禁止加音乐，禁止加文字和标注。禁止加音效。禁止改变人物台词顺序。

### 5.3 【布光锁定】必须用英文写（关键）

中文布光词（「温暖的阳光」「柔和的阴影」）会被模型当成风格形容词自由发挥。
英文 8 维度写法 = 技术规格，模型的自由度被压到最小。

**8 维度拆解顺序**（自己写新模块时照此顺序）：

1. 影像基调与参照（什么流派、什么摄影指导）
2. 机身与镜头（画幅、景深、颗粒、光晕）
3. 色彩锚点（墙面/木饰面/石材/金属/玻璃各是什么颜色）
4. 曝光与影调（高光保留在哪、暗部压到几 IRE）
5. 光源构成（主光是什么、补光是什么、色温各是多少）
6. 运动方式（允许什么运镜、禁止什么）
7. 情绪定调（住家感 / 酒店感）
8. 声源清单（可听的环境声）

### 5.4 变量块的四条写法

**【参考】** —— 逐份声明角色，**这是唯一允许出现「图片N」的地方**：

```
图片1为爸爸，只作人物参考，保持其面孔、发型与服装；
图片2为男孩，只作人物参考，保持其面孔、发型与服装；
图片3为妈妈，只作人物参考，保持其面孔、发型与服装；
图片4为场景，只取其材质、色彩与光线，不作全景背景，不迁移其中任何人物。
```

顺序规则：**角色在前、场景在后**。

> **为什么正文不许写「图片N」**（真实事故）：
> 正文写「图片1为爸爸，图片1说……」→ 上画布时要把「图片N」全局替换成 `{{node:xxx}}`，
> 替换后正文里出现 `{{node:xxx}}说`，既重复引用又超 4000 字上限。
> **正确做法**：正文只写角色名「爸爸」「妈妈」「男孩」，只有【参考】块写「图片N为爸爸」。
> 上画布时只改【参考】块，正文一字不动。

**【故事背景】** —— 1–2 句，交代时间地点人物与这段在整片的位置。不写情绪形容。

**【画面内容】** —— 本段核心。只写**摄影机拍得到的东西**：谁在哪、手在做什么、身体朝哪、眼睛看谁、说什么。禁止心理描写、括号暗示、比喻。

**【镜头】** —— 逐镜行，每行六要素：

```
镜头一（0-4秒）：光圈 f/4（中等景深，背景轻微虚化），焦段 28mm（全景），
平视稳定器侧向跟移（lateral gimbal tracking）；三人从画面右侧依次走入画面，
妈妈在最前、男孩在她身侧、爸爸在最后，男孩经过画架时右手在画架边缘轻轻带过。
```

六要素：**时间戳 + 光圈(景深) + 焦段(景别) + 机位/运镜 + 主体动作 + 落点**。
时间戳必须闭环：0-4、4-9、9-15…**首尾相接、总和等于段时长**，写完必查。

### 5.5 特写三件套与视线因果（用户点名的视听语言规则）

**用户原话（2026-10-31）**：

> 「避免使用一镜到底、创意转场（不绝对禁止），我们整个片子的基调不适合这样做。
> 多去打角色的特写，可以把我们整个片子的基调想象为一个 MV，无声，但是通过镜头的调度来实现节奏感。
> 不要去出现其它支线，我们要尊重原始大纲。
> 可以出现类似脚步特写，来说明进入新地点。出现手部特写，来强调微观动作。
> 加入眼神面部特写，来强调看到了什么——你要有视听语言逻辑，眼神特写之后应该接上看到的物体。」

**特写三件套（各管一件事，不能混用）**：

| 特写类型 | 功能 | 必须接什么 |
|---|---|---|
| **脚步特写** | 说明**进入新地点** | 接新环境的中景/全景 |
| **手部特写** | 强调**微观动作**（开柜门、拍地面、翻衣领） | 接该动作的结果或对象 |
| **眼神/面部特写** | 强调**看到了什么** | **必须接上她看到的那个物体** |

> **最容易翻车的一条**：眼神特写之后不接对象 → 观众不知道她在看什么，镜头变成无意义的漂亮脸。
> 正确写法：「她抬头看向斜上方的高窗（特写）→ 下一镜：高窗的光落在墙面（中景）」。

**禁止项**：

- 一镜到底（除非全片基调就是长镜头）
- 创意转场（叠化/划像/旋转等）
- 支线叙事（尊重原始大纲，不自行加戏）

### 5.6 提示词的七个「不」，每一个都有真实代价

| 不写 | 原因 | 真实事故 |
|---|---|---|
| 不写负面词 | 负面词会被反向诱导（写「不要滑板车」→ 出现滑板车） | 「画面整洁无任何滑板车」→ 反而画出了滑板车 |
| 不写字幕/文字 | 模型会把文字画进画面 | 片尾字幕在画面里成了乱码 |
| 不写 BGM | BGM 属后期，模型会生成噪音 | 【限定】固定写「禁止加音乐」 |
| 不写心理/比喻 | 模型无法执行 | 「他心里五味杂陈」→ 无意义画面 |
| 不写小数秒 | 即梦只接受整数秒 | 5.5 秒被服务端拒绝 |
| 不写文件名 | 文件名泄漏会判为素材绑定错误 | 「刀客甲.png」导致提示词被判非法 |
| 不写多机位并联 | 一镜一机位，模型不会切换 | 「先俯拍再平视」→ 画面抖动 |

## 6. 量化基准表（五版最终产物实测，可直接当验收标准）

| 指标 | 周末听谁的<br>(v2 镜头级) | 129 户型篇 | 狮山·45 镜版 | 狮山·30 镜精简版 | **方法论取值** |
|---|---|---|---|---|---|
| 成片时长 | 70 秒 | 91 秒 | 120 秒 | 120 秒 | 60–130 秒 |
| 生成段数 | 9 | 9（+2 备选） | 15 | 15 | 9–16 |
| 总镜数 | 27 | 22 | 45 | 30 | 20–45 |
| 平均单镜 | 2.6 秒 | 4.1 秒 | 2.7 秒 | **4.0 秒** | **2.5–4.5 秒** |
| 每段镜数 | 2–4 | 2–3 | 1–4 | **1–3** | **2–4** |
| 每段时长 | 4–12 秒 | 5–15 秒 | 7–9 秒 | 6–10 秒 | **4–15 秒** |
| **每段字数** | **2917** | **2611** | **2547** | **2786** | **2400–3300** |
| 11 区块齐全 | 9/9 | 11/11 | 15/15 | **15/15** | **100%** |
| 参考图张数 | 19 | 19 | 24–34 | 24–34 | 按需，不凑数 |

> **字数中位 ≈ 2650，跨越 9 段/15 段、2.6 秒/4.1 秒每镜、有台词/无台词，几乎不变。**
> 这是最强的规律：**一段提示词的信息承载量是恒定的**，不由段长决定。
> 段长 6 秒和 15 秒的提示词字数差不多（2500 vs 2900），差别在于镜头数而非描述密度。

**推导关系**：

```
台词总字数 ÷ 4.5字/秒 = 台词占用秒数
总秒数 − 台词秒数 = 留给动作/空镜/定版的秒数
总秒数 ÷ 4秒/镜 ≈ 总镜数          (2.5–4.5 秒/镜，越快越碎)
总镜数 ÷ 2~3镜/段 ≈ 段数
段数 × 2650字 ≈ 提示词总字数
```

**两种节奏风格（按题材选，不要混）**：

| 风格 | 秒/镜 | 适用 | 实例 |
|---|---|---|---|
| 叙事快节奏 | 2.5–2.7 秒/镜 | 有台词的人物戏、短剧 | 周末听谁的（27 镜/70s）、狮山 45 镜版 |
| 氛围慢节奏 | 4.0–4.1 秒/镜 | 形象片、无台词/少台词、地产 Atmos | 狮山 30 镜精简版、129 户型篇 |

> 用户真实反馈原话：「现在每个镜头之间像是强行拼接而成，完全没有视听语言逻辑」
> 与「T04，现在一直特写孩子的时间太长了」——**节奏是唯一必须靠人看片判断的指标**，
> 量化表只能给出区间，具体落在哪一端由题材与素材决定。

## 7. 12 项自检 + 机械校验

### 7.1 骨架阶段（12 项，不过不进下一步）

1. 时长与台词量是否匹配（按 4.5 字/秒核算）
2. 每个镜头是否只装一个信息
3. 叙事目的是否具体到视听手段（不是「表现温馨」）
4. 镜头组是否连贯（递进/因果/蒙太奇/对比）
5. 场景与素材是否一一对应
6. 动作是否有因果链（不是状态罗列）
7. 台词是否口语化
8. 全场次是否有卖点遗漏
9. 空间逻辑是否成立（洋房不是一楼、室内不是庭院）
10. 人物是否持续在场（三人同框类要求）
11. 转场是否有依据（动作匹配/方向延续/视线引导/声音桥）
12. 时长是否整数秒

### 7.2 提示词阶段（可机械判定，写成脚本跑）

以下规则全部来自狮山项目的实际校验脚本（`validate_exec.py` / `check_logic.py` / `merge_storyboard.py`），
**是真实拦下过错误的硬规则**，不是设想。

**结构类**

| 校验项 | 判定方法 | 阈值 |
|---|---|---|
| 区块齐全 | 正则 `^##\s*【(.+?)】` 切块 | 11/11，缺一即错 |
| 时间戳闭环 | 提取 `镜头N（x-y秒）`，`y_i == x_{i+1}`、`x_0 == 0`、`y_last == 段生成秒数` | 容差 1e-6 |
| 逐镜行数 | 统计 `镜头[一二三…]+（` 出现次数 | == 该段镜号数 |
| 段时码 = 首末镜 | 段头 `(m:ss-m:ss)` vs 镜行时码 | 完全一致 |
| 镜号连续 | 全片镜号集合 | == `range(1, N+1)` |
| 生成秒数 ≥ 成片秒数 | `gen >= film` | 且 `gen >= 4`（即梦下限） |
| 每段镜数 | 计数 | 1–3（推荐 2–3） |
| 字数 | 去空白计字符 | 段 2400–3300；整段正文超 4000 即超模型上限 |

**字段白名单类**（防自由发挥）

| 字段 | 允许值 |
|---|---|
| 摄影角度 | 平视 / 俯拍 / 微俯拍 / 仰拍 / 极高俯拍 / 低机位（**6 值，超出即错**） |
| 景别 | 特写 / 近景 / 中景 / 全景 / 远景 / 大远景 / 中近景 / 中远景 / 微距（**9 值**） |
| 运镜（英文） | locked-off / slow dolly push / slow dolly in / gimbal tracking / lateral tracking / slow tilt down / static shot（7 值） |

**禁用词类**（FORBIDDEN，实测 22 词）

```
项目外地名/地标：东方之门 / 金鸡湖 / 游船 / 大剧院 / 科技馆
不存在的空间：儿童房 / 保姆房 / 衣帽间
违规内容：泳装 / 比基尼 / 泳者 / 豪车 / 香槟酒 / 红酒 / 沙盘 / 售楼处
引用写法：图片1 / 图片2 / @图片 / 参考图片
Markdown：**
技术尾巴：fps / 码率 / 1080p / 4K / 720p
```

**软约束（警告级，超了要人看）**

| 项 | 区间 |
|---|---|
| 九列表「画面内容」字数 | 40–220 字 |
| 九列表「叙事目的」字数 | ≥ 8 字 |
| 整片总时长 | 与目标差 ≤ 1 秒 |

**一致性类**

| 校验项 | 方法 |
|---|---|
| 4 个真常量块与通用提示词包逐字比对 | 全文匹配，改一个字符即报错（实测有 7.9% 静默漂移，必须 diff） |
| 3 个参数化常量块的参数正确 | 按段落类型（室内/空镜/户外、有台词/无台词）抽查 |
| 素材数一致 | 段内 `图片N` 的最大 N == 该段素材数 |
| 台词完整 | 从执行脚本抽台词，逐句在提示词原文中查找 |

> **⚠ 最重要的一条：信息点终检（真实丢过）**
>
> 129 户型篇的 V4 主版本里，孩子的台词「我要去泉屋买零食！」**出现 0 次**——
> 它只活在附录的 V6 备选版里。这是一条**信息点级丢失**，而每一段单独校验都是合格的。
>
> **所以交付前必须做最后一次终检**：
>
> ```
> 拿 Step 0 的信息点清单（N 条），逐条在最终提示词里搜索，
> 确认「这条信息是否有对应的台词或画面」。
> 缺一条就不能交付。
> ```
>
> 这个校验无法被"段级校验"覆盖——因为丢失的往往是**跨段的台词归属**（这句台词被拆段时漏了）。
> 同理要查：**提示词段数是否等于执行脚本的任务数**（129 项目里 9 段 ≠ 10 任务，T07 被拆了）。

> **⚠ 常量块之间可能自相矛盾，必须人工过一遍**
> 狮山项目的真实内伤：【限定】写「禁止加音效」，而【设定】写「环境声与物理音效同步触发」，
> 导演脚本里还列了 7 个音效设计点。三条互斥，却逐字复制进了 16 段提示词与 15 个画布节点，**没有任何脚本能查出**。
>
> **规则**：写完常量块，逐对检查互斥——「禁音效」vs「写环境声」、「绝对无外人」vs「允许虚化路人」、
> 「禁止文字」vs「场景既有标识保真」。**这是目前唯一无法自动化的校验项。**

### 7.3 三个项目踩过的坑（固化成规则）

| 坑 | 症状 | 规则 |
|---|---|---|
| 素材错配 | 台词说学校，图是小区大门 | 先做台词→场景卡映射表 |
| 人物消失 | 「孩子和妈妈不见了」 | 每镜写死三人在画左/右/中 |
| 动作随机 | 男孩乱动 | 手/身体朝向/视线三件套写死 |

| 负面词反噬 | 写「不要滑板车」→ 出现滑板车 | 正面陈述：「男孩双手空着」 |

### 7.5 用户的验收词典（怎么判断过了 / 没过）

**最重要的观察**：用户**从不评价过程，只说否定式的定位词**。

**「通过」的形态不是形容词，是下一个执行动词**：

```
「跑吧」「开始」「都开始吧」「全部开始」「A」「写入吧」
```

看到这些词就是过了。反过来，**只要出现下面 8 族词之一，就是没过**：

| 族 | 用户原话 | 含义 | 对应改法 |
|---|---|---|---|
| **多** | 「改得有些多了」「镜头太多太碎」 | 做过头了 | 减：删镜、删描述、删改动 |
| **碎** | 「每个小空间都硬切一遍」「拆得太碎了」 | 粒度太细 | 并：合镜、合段 |
| **快** | 「太久了」「现在是有些问题」 | 节奏不对 | 调：改时长、改镜数 |
| **假** | 「像口播广告」「不像剧情 TVC」 | 不像真的 | 换：改说法、改动作 |
| **灰** | 「画面灰」「不干净」 | 影调不对 | 调布光常量块 |
| **刻意** | 「太刻意」「像偷窥视角」 | 手法过载 | **同一手法连用 ≥2 次即判刻意** |
| **奇怪** | 「有些奇怪」 | 逻辑或空间不成立 | 查：空间/动线/连续性 |
| **对不上** | 「配图和台词完全对不上」 | 素材错配 | 查：台词→场景卡映射 |

**两条元规则**：

1. **反向失败成对出现**：「改得有些多了」↔「有些太拘谨了」——同一个问题被两个方向各打回一次。
   合格区间只有一条：**零信息丢失 + 更自然**。
2. **低层不合格时，用户不会提高层**。逻辑/配图不对时，不会跟你说「画面不够美」。
   先修逻辑，再谈审美。顺序错了会被连续打回。

**语气升级 = 失败信号**：同一条规则被违反第 3 次，用户语气会从「又」升级到「搞叉了」。出现这个就是前面几轮没真正修复。

### 7.6 22 条跨会话硬规则（出现频次排序）

| # | 规则 | 频次 |
|---|---|---|
| R4 | **一切以角色卡/场景卡为准，不得擅自换装**（「不要让女主没有缘由的频繁换衣服」） | 12 |
| R2 | **必须给 LLM 看图**，「没给它看图」是默认第一嫌疑人 | 8 |

| R6 | 禁止字幕（片尾定帧也不加任何文字） | 6 |

### 7.7 整片级验收（最容易漏的一层）

> **用户原话**：「这并不像一个剧情 TVC 广告，而是一些片段拼凑。」

这是**最致命的失败模式**：每一段单独看都合格、每镜都对、11 区块齐全，
但连起来看不成立。**因为它缺一个产物层：整片叙事与衔接设计。**

单段验收器查不出这类问题。必须单独做整片验收：

| 项 | 问句 | 不通过的症状 |
|---|---|---|
| **三幕** | 有没有建立-对抗-解决？结尾是否收在开头埋的点上？ | 平铺直叙，看完没印象 |
| **每段存在理由** | 删掉这段，故事是否受损？ | 删了不影响 = 可以删 |
| **接缝衔接** | 相邻两段之间，有没有显式的「出点 → 入点 → 衔接手段」？ | 「强行拼接而成，完全没有视听语言逻辑」 |
| **衔接手段** | 每一处接缝至少用上 2 项（动作匹配/方向延续/视线引导/声音桥/光线延续/景别变化） | 硬切、跳、方向反转 |
| **景别节奏** | 有没有「中景切中景」？ | 剪辑无呼吸感 |
| **人物在场** | 主角是否全程有动机地存在？ | 「孩子和母亲会消失」 |
| **调性一致** | 有没有手法过载？（背影、前景虚化连用 ≥2 次即「刻意」） | 「像偷窥视角」「太刻意」 |

**衔接设计表**（执行脚本里应有一张，或至少逐镜写清）：

```
| 段 | 出点（这一镜怎么结束） | 入点（下一镜怎么开始） | 衔接手段 |
| T02 | 妈妈拍地面后抬头 | 爸爸低头看她 | 视线引导 + 声音桥 |
```

> **"剧情 TVC" 与 "片段拼凑" 的唯一区别**：前者每个接缝都有手段，后者只是把好看镜头排在一起。

## 8. 一键执行 SOP（你给大纲，我按这个跑）

> **执行细节（每步的问话、输入、产出模板、展示格式、返工处理）在 `guided-production-flow.md`。**
> 本节只给骨架，实际带用户走流程时以那份为准。

```
【输入】脚本大纲（docx/md/文本）+ 时长目标 + 素材现状

Step 0  诊断      输出「问题清单 + 信息点清单」→ 你确认
Step 1  台词定稿   信息点清单法重写 → 逐条核对 → 你确认
Step 2  导演骨架   00-导演骨架.md（定调/节奏/九列表/任务划分/12项自检）
Step 3  执行脚本   01-执行脚本-正式版.md（台词锁定/映射表/六列分镜/任务/备注/素材清单）
Step 4  提示词     02-即梦提示词-可提交版.md（常量块拼装 + LLM 写变量块 + 机械校验）
Step 5  交付      md + docx；如需上画布，再走素材节点与卡片创建
```

**三个强制暂停点**（必须你点头才继续）：
1. Step 0 后（诊断与信息点清单）
2. Step 1 后（台词定稿）
3. Step 3 后（执行脚本 = 生产排程）

**为什么暂停在这三处**：这三处改一次，下游全部重做；过了 Step 3 再改台词，等于整片重跑。

## 9. 改稿协议（用户怎么给意见，我该怎么改）

真实记录：一个 90 秒片子在提示词阶段被微调了 **81 轮**。这些轮次不是随机的，能归纳成五类。

### 9.1 五类修改意见与响应方式

| 类型 | 用户原话特征 | 怎么改 | 不要做什么 |
|---|---|---|---|
| **① 定位级微调** | 「T04 孩子从画面左侧出画，不要有向下走的感觉」 | 只改这一段这两个要素 | 不要顺手改别段，不要重写整段 |
| **② 全局规则** | 「三人始终同框」「男孩每个动作写死」「不要出现小数秒」 | 写进执行备注/常量块，全片统一 | 不要逐段打补丁 |
| **③ 写法参照** | 直接贴出一整段满意的提示词 | **当作 few-shot 锚**：抄它的句式与详略度 | 不要只抄内容不抄结构 |
| **④ 模型能力问题** | 「有的画面孩子和母亲会消失，是提示词问题还是模型级别太低？」 | 先分离变量：换更细的写法 vs 换模型 | 不要直接认定是模型问题就换模型 |
| **⑤ 方向性否决** | 「不要给 Gemini 这么多限制」「你得给它所有的图片」 | 调 LLM 输入的约束强度 | 不要以为是自己写错了 |

### 9.2 三种「改法」的选择标准

```
改一句 ──→ 问题只涉及某一句台词/某一个动作
改一段 ──→ 问题涉及机位、景别、镜头顺序（重写【镜头】该段逐镜行）
整片重写 ─→ 问题涉及节奏、结构、人物关系
```

> **代价对比**：改一句 1 分钟；改一段 5 分钟；整片重写 40 分钟 + 全部重跑生成。

### 9.3 三条铁律

**① 改卡不删卡**（真实事故：18 张视频卡的上游连线全变死链）

```
✅ node edit video --node-id <id>
❌ node delete + node create
```

删了再建会换新 nodeId、丢上游连线，画布上还会堆垃圾节点。

**② 给 LLM 看图，不要只给它文字**

真实往返：
- 「让 Gemini 写，给它看图」→ 结果还行
- 「你得给它所有的图片，让它结合场景人物，不一定全程都是妈妈的特写！」→ 才到位

只喂文字时，LLM 会凭空发明空间；喂了图，它会描述真实存在的物件。

**③ 约束的强度要试，不是越细越好**

真实反馈链：「不要给 Gemini 这么多限制」→「告诉它台词，让它不要改变参考图中的空间，整段视频以角色特写为主，鼓励多镜头」

约束分三层，按需加：

| 层 | 内容 | 什么时候给 |
|---|---|---|
| 事实层 | 台词原文、参考图里的空间与陈设 | **永远给** |
| 意图层 | 这段要表达什么、以谁为主、多镜头还是长镜 | 默认给 |
| 执行层 | 具体几分镜、每镜几秒、光圈焦段 | **只在它跑偏时给** |

### 9.4 用户会贴「满意的版本」当锚

真实行为：用户在某轮直接贴出一整段完整的 11 区块提示词，说「使用这一版来改吧」。
**这是最高效的信号**——它不是让我照抄内容，是让我照抄**句式、详略、信息密度**。

处理方式：
1. 存为 few-shot 样例
2. 后续所有段按它的详略度写
3. 不要把它当模板填内容（会丢具体性）

## 10. 演进史：哪些做法被淘汰了、为什么

三个项目不是三次重复，是**三代方法**。知道每一代错在哪，才不会退回去。

| 维度 | 第一代（2026-10-17） | 第二代（10-18/19） | 第三代（10-25 起） |
|---|---|---|---|
| 编排单位 | **「场」**，一个任务 = 一场戏（约 9.5 秒） | 按镜拆段（T01a/T01b） | 镜 + 任务双轨 |
| 分镜表 | **完全没有** | 九列分镜表成型 | 九列 → 六列 → 逐镜行 |
| 镜的粒度 | 段内中文「切画面」串 3–6 个节拍 | 时间戳闭环，2.4 秒/镜 | 4.0 秒/镜（每镜一信息） |
| 时长怎么定 | 抄脚本自带时间 / 手填 | 台词字数 ÷ 4.5 字/秒 反算 | 同二代 + 每镜一信息约束 |
| 【镜头】区块 | 一行常量「稳定机位与极缓慢推轨。自然切镜。」 | 「分镜：」逐镜行（时间戳+光圈+焦段+动作） | 同二代 |
| 素材绑定 | **三条路并行**：`[image]` 占位 / `{{node:xxx}}` / 裸标签`图片N` | 统一 `图片N` + 表格声明 | 同二代 + 正文禁写编号 |
| 布光锁定 | 段内联，**但同项目并存两套互斥版本** | 全片逐字相同（视觉指纹） | 提取为「通用提示词包」 |

### 10.1 第一代最严重的三个裂缝（都是「缺一层」导致的）

**裂缝 1：时长三本账对不上，且无任何校验**

同一项目里存在三个互不一致的时长：

| 文件 | 声明时长 |
|---|---|
| `submission-tasks.json` | 55 秒 |
| `submission-tasks-建发风格.json`（实际提交物） | 81 秒（`_meta` 里却仍写 55 秒） |
| `v4-submits.json`（真实提交记录） | 76 秒 |

**根因**：没有执行脚本这一层，就没有「任务 → 镜头 → 秒数」的可核算汇总表。
**解法**（现在的方法论）：执行脚本第四节「任务划分」必须有合计行，且总秒数 = 各任务秒数之和，机械可验。

**裂缝 2：同一项目内并存两套互斥的【布光锁定】**

- `task1-3.prompt.txt` 用 A 版：`high-end residential lifestyle film / no grain / locked-off`
- 提交 JSON 用 B 版：`premium family lifestyle film / fine organic grain / fast prime / honey-oak`

两版在**规范明文禁止的维度上正好相反**（no grain vs fine grain）。说明当年「8 维度常量块」只是写下来了，没有锁死。

**解法**：常量块提取为独立「通用提示词包」文件，每段整块复制，并在机械校验里加一条**逐字比对**。

**裂缝 3：素材绑定三条路并行**

规范写 `[image]/[audio]` 占位（自注「不是提交格式」）、prompt 用 `{{node:node_xxx}}`、提交 JSON 用裸标签 `图片2/音频1`。三套编号体系互不兼容。

**解法**：见 §5.4——正文只写角色名，【参考】块写「图片N为X」，上画布时只替换【参考】块。

### 10.2 第一代里被丢掉、但其实很好用的 4 件资产

这四件在后续版本里消失了，值得按需捡回。

**① 私密 / 公共空间的背景人物分层**（现在只剩「绝对无人」一句）

| 空间类型 | 规则 |
|---|---|
| 私密（卧室、客厅） | 绝对无外人，仅一家人或主角独处 |
| 公共（园林、会所、大堂、街道、场馆、商业、地铁） | 允许 1–3 位住户作中后景虚化背景；**不直视镜头、不与主角互动、不遮挡主角、穿着得体举止安静**；主角始终唯一视觉重心 |

> 这条的价值：公共空间如果写「不要路人」，会得到一个空城；写「允许虚化背景」才能得到真实生活感。
> 真实项目里这条被压缩成一句「除了一家人绝对不可能有其他人」，只适用于室内。

**② 参考图的反向排除清单**（现在只剩正向的「只取其材质与光线」）

第一代写法：

```
参考图1 = 该空间的唯一依据（画面里的空间与陈设全部取自这一张）
参考图2 = 只借焦段、透视与光比，其中元素一律不得入画，两个空间绝不可混合
```

现在只剩「只取其材质、色彩与光线，不作全景背景」——**「绝不可混合」这句反向禁令没了**。
而真实事故恰恰是混合：模型把客厅的沙发搬进了入户厅。

> **建议**：场景参考图 >1 张时，必须写「不得混合 / 元素一律不得入画」。

**③ 音色三件套**（现在只剩「音色：妈妈、爸爸」一行）

| 件 | 内容 |
|---|---|
| 6 维画像 | 年龄/方言/基频（男 100–120Hz、女 200–230Hz、童 300–350Hz）/语速（4.2–5 字每秒）/音色质地/口头习惯 |
| 每人一句基准台词 | 用于锁定音色一致性 |
| 三人共用对比句 | 同一句话三人各说一遍，用于横向校准 |
| 技术规格 | −16 LUFS、3 遍取中位 |
| 验收 5 条 | 音色是否可辨、语速是否自然、有无电子音、情绪是否匹配、三人是否可区分 |

**④ 17 词语气词库**（唯一一份「表演词典」）

`嫌弃地 / 不以为然地 / 无奈地 / 得意地 / 心虚地 / 讨好地 / 笃定地 / 试探地 / 敷衍地 / 认真地 / 随口地 / 认真地 / 心疼地 / 骄傲地 / 小声地 / 急急地 / 讪讪地`

> 现在统一降为整段一句「语速偏快、有家常抢白感」。**短剧的信息密度靠语气承载**，
> 当某一段需要明确情绪转折时，从这 17 个词里挑，比写一句抽象描述更有效。

**⑤ 结尾钉子**（逐镜行体系里没有等价物）

第一代有「最后一镜保持固定机位，不拉远」这类结尾约束。现在【镜头】写成逐镜行后，
结尾镜的特殊机位要求容易被漏掉。**建议**：最后一镜若有机位特例，单独在【限定】里再写一次。

## 11. 「一键」到底能到什么程度（诚实版）

方法论是完备的，**自动化程度是不完备的**。说清楚边界，避免你期待落空。

### 12.1 已经固化的（给大纲就能跑）

| 环节 | 状态 |
|---|---|
| 四阶段产物格式 | ✅ 已固化（本文档即规格） |
| 九列分镜表 / 六列执行脚本字段 | ✅ 已固化（白名单 + 正则可验） |
| 11 区块模板 + 7 个常量块 | ✅ 已固化（通用提示词包可直接复用） |
| 74 条机械校验规则 | ✅ 已实现（`validate_exec.py` 系） |
| LLM 调用契约（一次写整片/分段写提示词） | ✅ 已验证 |
| 素材→节点→卡片→生成 | ✅ 已固化（画布 CLI 六段链路） |

**实际能承诺的**：你给大纲，我按步骤产出**四个文件 + 通过机械校验**，中间的三个暂停点由你确认。
一次 90 秒片子的四阶段产出，约需 5–8 轮交互（不是真的"一句话出片"）。

### 12.2 还没自动化的（真实缺口）

**缺口 1：没有编排器**

狮山项目有 60+ 个 Python 脚本，但**没有 `run_pipeline`**；`gemini_call.py` 全库零调用方——
每次 LLM 调用都是人工敲命令。所以"一键"目前是**Agent 按文档执行**，不是脚本一键跑完。

**缺口 2：没有状态机**

用文件名当状态（`01_` / `20_` / `40_` / `63_`…），同阶段有 3–6 个版本并存，没有「当前版」标记。
改了 `30_通用提示词包.md`，不会让 `40_即梦提示词脚本.md` 失效——**下游不知道自己过期了**。

**缺口 3：提示词生成层是断点**

16 段的创意正文曾硬编码在 `gen_prompts.py` 的 `SEGMENTS` 里，没有对应的生成 prompt。
换一版文案要改 Python 源码（`fix_timecodes.py` 就是靠字面替换改源码来修时码的）。
**这是最该先补的一处**：把 S7 从"拼装"改成"LLM 生成 + 机械校验"。

**缺口 4：校验器硬编码具体项目**

`MUST_COVER` 是这 16 段的关键词表、画布 UUID 写在脚本里、绝对路径写死。
**换项目 = 改源码**。这是它没成为通用工具的直接原因。

**缺口 5：素材映射有四份手维护 JSON**

`node_v3` / `node_map` / `node_revised` / `video_v15` 四份文件描述同一批节点，没有单一真源。

### 12.3 我的建议：下一步补什么（按性价比排序）

| 优先级 | 补什么 | 收益 |
|---|---|---|
| **P0** | 把 74 条校验规则抽成一个**参数化脚本**（项目名/段数/关键词表当参数） | 换项目不用改代码 |
| **P0** | 加一个 `manifest.json` 记录「当前版 + 上游哈希」 | 解决过期不知道自己过期 |
| **P1** | 把 S7 的 `SEGMENTS` 换成「LLM 生成正文 + manifest 校验」 | 换文案不用改源码 |
| **P1** | 素材映射统一为一份 `assets.json`（素材名 ↔ 文档图片N ↔ nodeId） | 消灭四份 JSON 漂移 |
| **P2** | 写 `run_pipeline.py`：四阶段串起来，每个阶段结束跑校验、失败即停 | 真正的"一键" |
| **P2** | 失败分流：截断 → 降档重跑；字数不足 → 换短 prompt | 不用手写 rerun 脚本 |

> **现状一句话**：**格式与规则已经一键化，执行还没。**
> 现在给大纲，稳定能得到"结构正确、校验通过"的四个文件；
> 要做到"敲一个命令出片"，还差上面 P0/P1/P2 这六步。
