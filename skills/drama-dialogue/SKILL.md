# 台词定稿（信息点清单法）

> 规则依据：`outline-to-jimeng-pipeline.md` §2.3（这是返工最多的一步，连续 6 轮被驳回后总结出来的方法）。

## 输入 / 产出

- 输入：`00-诊断报告.md` 的信息点清单 + 字数配额
- 产出：`01-台词定稿.md`（逐句定稿 + 信息点 N/N 核对）

## 方法（v3 信息点清单法，采纳版）

1. 把原文逐句拆成**信息点**（一句通常 2–4 个）；
2. 让 LLM 重写台词，**只约束「信息点必须全在」，不约束用词**；
3. **两轮**：
   - 第一轮：只求自然（会写胖）
   - 第二轮：只瘦身（删水不删信息）
4. 逐条核对信息点，输出 N/N；
5. 台词逐句锁定，进入不可变状态。

## 调用

`creative_writer(kind=script, thinking=high)` —— 台词属剧本类，走 Gemini。

给 LLM 的措辞（照抄）：

```
下面是台词的信息点清单（N 条）与字数配额（X 字 ± 10%）。
请把这些信息点全部保留，用口语重写；不要求保留原句措辞。
改写后我会逐条核对信息点，缺一条即不合格。
```

## 产出：`01-台词定稿.md`

```markdown
# 台词定稿（N 句 / X 字）
| 场次 | 角色 | 台词（定稿） |
## 信息点核对
| # | 信息点 | 落在哪句 | ✓ |
```

## 只允许四类改动

口语化 / 合句 / 调顺序 / 去赘词。**不允许**增删台词、改变意思、加负面信息、绕路。

## 验收

- [ ] 信息点 N/N 全在
- [ ] 改动都在四类之内，逐句给用户看「原文 → 定稿」
- [ ] 字数在配额 ±10%

## 常见返工（按用户原话）

| 用户说 | 改法 |
|---|---|
| 改得有些多了 | 回退，只保留必要改动 |
| 有些太拘谨了 | 放开，不要逐字守壳 |
| 不要中途停靠一次，不要加这种负面信息 | 删掉所有负面/绕路的添加 |
| 把每句话拆得太碎了 | 一段话整体交给 LLM，不要一句一句喂 |
