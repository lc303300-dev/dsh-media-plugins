# 通用视频导演提示词

把需求当成一场可观看、可执行的拍摄来设计。资料负责回答"怎样拍"，模型选择、标签语法、时长与分辨率限制交给下游平台适配器。

## 工作流程

1. 提取戏剧转折、动作因果、情绪落点和结尾画面。
2. 建立连续性锚点：角色、服装、道具、空间、时间、天气、运动方向和状态变化。
3. 补齐首帧的主体位置、朝向、视线、前中后景、相机位置与主光方向。
4. **先选模板**（按"有没有分镜、要不要卡点、有没有参考视频"）：
   - 有分镜、逐镜推进 → **T1 `镜头N` 编号式**（相邻两镜可合并为 `镜头1-2`）
   - 有分镜、要精确控制每段时长与节奏 → **T2 时间轴式**（`0-1.5秒:` 或 `[00.0-03.0秒|场景名]` + 区块头）
   - 一个镜头、镜头内有连续变化（延时/渐变/变形） → **T3 单一镜头 · 内部时间轴**
   - 一个镜头、运动不中断、不要时间轴 → **T4 单镜头连续（一镜到底式）**
   - 有参考视频、要迁移它的运镜/动作 → **T5 视频驱动**
5. 分开编写主体运动与相机运动；每次运镜都要服务于信息、情绪或转场。
6. 把抽象情绪翻译成眼神、呼吸、肌肉、停顿、手部动作和空间关系。
7. 加入必要的质量约束与连续性锁定，避免堆叠无关术语。
8. 输出中文提示词；首次出现专业术语时采用 `English term（中文释义）`，后续可使用更简洁的一种写法。

## 资料读取路由

- **先读 [即梦提示词模板集](references/jimeng-standard-template.md)**：它是模板选择、素材角色、编号映射与允许/禁止写法的**唯一真源**。
- 每次创作都读 [导演方法](references/directing-methods.md)，用于可视化表达、场面调度、表演、光色、物理与声音。
- 需要确定要素语义、素材语义、风格分布或转场写法时，读 [提示词结构](references/prompt-structure.md)。
- 需要特殊视角、高速动作、复杂转场、极端 FOV 或社区实战技巧时，读 [社区与实验技巧](references/community-techniques.md)。
- [即梦模板速查](references/structure-guide.md) 只作快速落笔用，内容与正本重复时以正本为准。

## 证据与适用性

按以下等级理解引用资料，不把经验性写法宣称为平台保证：

- **官方范例**：最高等级（13 份官方范例是模板来源）。与下列任何等级冲突时以官方范例为准。
- **通用原则**：来自电影语言、视觉叙事或跨模型稳定实践，可默认采用。
- **社区经验**：创作者反复使用的启发式方法，按镜头需要选用并接受模型差异。
- **实验性启发**：适合小范围试验的精细协议或数值锚点，不能保证复现。
- **平台约束**：标签、参数、素材上限等仅由当前生成平台的适配器决定，不写成本技能的通则。

## 输出规则

- 默认交付一个可独立使用的中文提示词；用户要求时再附导演方案、分镜表或解释。
- **同一层只用一种分段手段**：`镜头N`、时间码/秒数区间、或镜头内阶段时间轴，不要混用。
- 段落结构按所选模板给：T1 每镜一段；T2 挂 `[素材说明]`/`[整体设定]`/`[时间轴]`/`[稳定性限制]`，每段音效单独成行；
  T3 先声明"这是一个镜头"再写内部时间轴；T4 声明 `一镜到底` 并按事件顺序写；T5 第一句写 `严格参考:`。
- T1 整段应覆盖：主体动作、素材绑定、景别/机位、主导运镜（范例实测覆盖率 11/11、10/11、9/11、7/11）；
  **个别镜可省略**、素材可沿用上一镜，**次序灵活**。
- 排斥项与局部约束**内联在需要它的那一句**里，不做段级负面清单（T2 的 `[稳定性限制]` 是范例认可的集中约束段）。
- 光影写三层：`光影: <光源层>，<光行为层>，<色调层>`；段级质感句可选，只在**末尾**写一次。
- **素材按角色逐份声明**（首帧/构图、场景、人物三视图、正脸五官、道具、配角、变形对象、多角色分配、参考视频），
  并写明**不要**从该源迁移什么。
- 保留 `blocking（场面调度）`、`whip pan（甩镜）`、`FOV（视场角）` 等有助执行的英文术语，但术语只用于描述画面，不作分镜骨架。
- 用中文裸标签 `图片N` / `视频N` / `音频N` 内联引用素材，**按图片 → 视频 → 音频的传入顺序重编号**；禁用 `@图片1` 与 `参考图片N`。
- 官方范例的库内编号与文件名（`图片27`、`图片28(2)`、`Stati..2.png`、`飞书202...7.mp4`）**不得进提交文本**，
  必须按传入顺序重编号（正本第七节有转换示例）；同一素材全片沿用同一编号。
- **不写技术尾巴**：模型名、帧率、码率、`15 seconds, 24fps, no subtitles` 一律交给结构化参数；
  画质与时长的自然语句写进 `[整体设定]`（如 `12秒，16:9，720p，写实电影质感`）。
- 用户未指定音频时追加 `不生成音乐，仅生成音效。`
- 不因案例来源标注了某个版本，就切换实际模型或把该版本限制带入资料层。
- 不承诺"100% 一致"或必然成功；改写为明确、可观察、可复核的连续性目标。

## 交付前检查

- **选了哪个模板？** 与"有分镜 / 单镜头 / 有参考视频 / 要不要卡点"对得上吗？
- **同一层只用一种分段手段**吗？（没有在同一批镜头上既写 `镜头N` 又写 `[00.0-03.0秒|…]`）
- T2：`[整体设定]` 是否写了时长/比例/分辨率/质感，是否声明了 `无对白 / 无字幕 / 无BGM`？每段音效是否成行？`[稳定性限制]` 是否覆盖恒定项与禁用项？
- T3：是否先声明了"这是一个镜头"，后文只写"镜头继续/拉回到"？变形类是否写了物理约定？
- 首帧是否非空且空间关系明确？
- T1 整段是否覆盖主体动作、素材绑定、景别/机位、主导运镜？（**个别镜可省略**——范例里就有没运镜、没景别的镜头；素材可沿用上一镜）
- 排斥项与局部约束是否内联在需要的句子里？段级质感句（若有）是否只在末尾写了一次？
- 素材是否**按角色逐份声明**？是否写了"不迁移什么"？
- 光影是否写了三层（光源 / 光行为 / 色调）？
- 所有情绪是否变成可见表演？主体动作和相机动作是否分别清楚？
- 镜头数量、节奏与时长是否现实？参考素材是否只在实际出现的镜头中引用？
- `图片N` 是否已按传入顺序重编号，同一素材是否同号，且无原始文件名 / `(2)` 残留？
- 是否残留管道符拼接标题、`@` 芯片、fps 或秒数技术尾巴？
- 角色、道具、光线、屏幕方向与状态是否连续？
- 专业英文是否被保留且有中文释义？社区或实验技巧是否按需使用？
- 模型版本、标签语法和输出参数是否留给下游适配器？
