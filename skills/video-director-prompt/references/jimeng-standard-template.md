> （连续多镜头 6 份、单一镜头 4 份、一镜到底 1 份、视频驱动 1 份）归纳为 **5 个模板 + 1 组共用配件**，
> 每个模板都写明**适用情况**与其来源范例。
>
> 本文件是 DSH 媒体能力包中唯一的即梦（Seedance / Dreamina）提示词结构标准。所有创作线
> （导演线 `video-prompt-orchestrator`、批次模式 `prompt_batch`、Skill 线 `video-skill-router`）
> 与所有知识文档都指回本文件，**不得在别处复制第二份模板**。
>
> **适用边界**：本文件只回答"怎么写"。模型与版本、时长 / 比例 / 分辨率、标签编号绑定、提交与轮询

## 〇、先选模板（决策表）

| 你的情况 | 用哪个 | 来源范例 |
|---|---|---|
| 有分镜设计，逐镜推进；镜头数量固定 | **T1 连续多镜头 · 镜头编号式** | 连续多镜头 01 / 02 / 03 |
| 有分镜设计，且要精确控制每段时长与节奏 | **T2 连续多镜头 · 时间轴式** | 连续多镜头 04 / 05 / 06 |
| 一个镜头拍完，镜头内部有连续变化（延时、渐变、变形、单镜头叙事） | **T3 单一镜头 · 内部时间轴** | 单一镜头 01 / 02 / 03 |
| 一个镜头拍完，运动不中断，不需要时间轴 | **T4 单镜头连续（一镜到底式）** | 单一镜头 04、一镜到底场景切换 |
| 有参考视频，要把它的运镜 / 动作迁移过来，换掉主体和场景 | **T5 视频驱动** | 视频驱动 |

> 多个模板可以**组合**：例如 T2 的时间轴 + T5 的视频驱动（`严格参考:xxx.mp4的运镜` + 时间轴分段）。
> 但**同一层只用一种分段手段**：同一份提示词里不要既用 `镜头N` 又用 `[00.0-03.0秒|…]` 分同一批镜头。

> **模板 ≠ 执行模式（2026-10-21 用户明确）**：模板只决定"这一条提示词里怎么分段"，不决定用哪种参考方式。
> 执行层默认**全能参考（m2v）**，`first_last_frame` 只在用户明确点名时使用；
> 用户给的是**一个整体时长**时，就是**一条视频、一个节点、一次生成**——本文的 `镜头N` / 时间轴是**同一条提示词的时间结构**，
> 绝不等于拆成多个视频节点分别生成。

## 一、T1 连续多镜头 · 镜头编号式

**适用情况**：故事有明确分镜、逐镜推进、镜头数固定、不需要按秒卡点。范例 01/02/03 都是这种。

```
[素材说明：谁是谁，各图什么角色]
[主体与场景约定]

镜头1：<本镜需要的信息；必写的只有 镜头N 编号本身，顺序灵活>
镜头2：<……>；
镜头1-2：<相邻两镜合并成一段（范例 03 的写法）>

[段级质感句，可选，放最后]
```

**该模板的实测共性**（范例 01/02/03 共 11 段）：

| 信息 | 覆盖 | 说明 |
|---|---|---|
| **主体 · 动作** | 11/11 | 每镜都写 |
| **素材绑定** | 10/11 | 可省略（范例 01 镜头2 靠上一镜同一素材沿用） |
| **景别 · 机位** | 9/11 | 范例 03 镜头4 没有景别 |
| **主导运镜** | 7/11 | 范例 02 镜头1 没有运镜 |
| 材质 · 细节 | 6/11 | 按需 |

**要点**
- 冒号可有可无（`镜头1` / `镜头2:` / `镜头3：`），**全篇保持一致**。
- 分镜之间用**分号或换行**皆可（范例都用 `;`，换行更易读）。
- **排斥项与局部约束内联在需要它的那一句**，不做段级负面清单。
- 段级质感句**放最后、可选**（范例 03 末尾 `真实拍摄质感，真实皮肤纹理质感。`；01/02 完全不写）。
- 顺序灵活：范例 01 镜头1 先写主体动作、再补景别与前景细节；范例 03 镜头3 先写动作、再给运镜、再给素材。

## 二、T2 连续多镜头 · 时间轴式

**适用情况**：多镜头且**要精确控制每段时长与节奏**，或段落需要命名（便于对位参考视频/音乐）。范例 04/06 是这种。

**两种分段写法（二选一，全篇统一）**

```
A. 秒数区间（范例 04）
0-1.5秒: 咖啡店玻璃门近景，……
1.5-3秒: 人物冲出咖啡店，……
3.-4.5秒: ……

B. 时间码 + 竖线标题（范例 06）
[00.0-03.0秒|穿过拥挤酒馆]
[03.0-05.5秒|撞翻餐盘并扶人]
[05.5-07.0秒|顾客反应与冲向门]
```

**范例 06 的完整区块（推荐骨架）**

```
[素材说明]
Stati..2 用于 Aura 的面孔、发型、身形和服装参考，全片保持一致；Stati..8 用于迎面走来的服务员；
图片55 用于酒馆尽头的大门；图片100 用于开门后的最终衔接画面。

[整体设定]
12秒，16:9，720p，写实电影质感。拥挤喧闹的木质酒馆，暖黄灯光……采用广角、正面倒退跟拍、
侧面跟拍、动作特写和顾客反应特写快速切换。无对白、无字幕、无旁白、无背景BGM，仅保留真实环境声与动作音效。

[时间轴]
[00.0-03.0秒|穿过拥挤酒馆]
<该段画面与动作>
<急促脚步、衣料摩擦、杯碟轻碰、人群惊呼>

[03.0-05.5秒|撞翻餐盘并扶人]
<该段画面与动作>
<金属餐盘震响、杯盘落地、液体泼洒、短促惊呼>

……

[稳定性限制]
Aura全片保持同一面孔、发型和服装，奔跑方向始终一致。……
```

**要点**
- **时长与画质写在 `[整体设定]`**（`12秒，16:9，720p，写实电影质感`），不要写进标题。
- **每段的音效单独一行**，用尖括号 `<…>` 包住；无对白时在整体设定里明说 `无对白、无字幕、无旁白、无背景BGM`。
- **`[稳定性限制]` 收尾**：写明全片恒定项与"不要慢动作 / 瞬移 / 穿模 / 肢体变形 / 空间方向跳变"。
- 需要"某段不可缩短"时**显式写死**（范例 06：`连续四秒推不开，不可缩短`，并逐秒拆解 1/2/3/4 秒）。
- 只要秒数区间、不要标题也行（范例 04 就没有区块头，直接 `0-1.5秒:`）。

**T2 与 T1 的分工**：T1 按"镜头"思考，T2 按"时间"思考。要卡点、要对位音乐、要精确节奏 → T2。

## 三、T3 单一镜头 · 内部时间轴

**适用情况**：**一个镜头拍完**，但镜头内部有连续变化——延时摄影、渐变、变形、单镜头叙事。范例 单一镜头 01/02/03。

```
[首帧 / 构图参考]
图片56为首帧参考，人物、摩托车、小狗保持一致。

[镜头定义：景别 + 运镜 + 主体，一句话交代整镜]
镜头从骑车男性上半身特写开始，持续缓慢后拉……

0-3秒: 人物上半身特写……镜头缓慢后拉……
3-7秒: 镜头继续后拉到半身景别……
7-11秒: 镜头后拉到中全景……
11-12秒: 镜头拉回到完整全景……人物猛地打出一个夸张的大喷嚏。

光影: <光源层>，<光行为层>，<色调层>
音效：……
禁止：任何文字、字幕、LOGO或水印
```

**要点**
- **先声明"这是一个镜头"**：写出起始景别 + 唯一运镜方向 + 主体，后文只描述"镜头继续…/镜头拉回到…"，**不引入第二个镜头**。
- **时间轴是该镜头的内部阶段**，不是分镜：每段都写"镜头继续…"、同一主体、同一空间。
- 内部需要切换时用**硬切声明**（范例 03：`CUT_02 硬切至极近距离俯视消防栓镜头`）——这仍是同一个连续镜头的内部切点描述，不写成 `镜头2`。
- **变形 / 替换类**必须写明物理约定（范例 03：`变化突然干净，保持相同占地位置，不出现粒子或渐变过程`）。
- 范例 02 是"单段 + 定长"的极简形态（只有 `0-4秒:` 一段），也属本模板。

## 四、T4 单镜头连续（一镜到底式）

**适用情况**：**一个镜头、运动不中断、不需要时间轴**（时间轴会破坏"连续"的表达）。范例 单一镜头 04、一镜到底场景切换。

```
[质感与镜头声明]
写实街头电影质感，手持纪实摄影。一镜到底。

[场景与素材锚定]
参考的图片32街道场景，有很多路人在行走……手持晃动镜头，模拟跟拍，画面轻微颠簸抖动。

[事件流：按发生顺序写，不切时间轴]
一位骑摩托车的男性图片102骑着摩托车从右往左快速入画，并停在画面中心……
镜头从左往右快速摇镜入画，轻微运动模糊……
背景街道有车辆驶过。

[可选：相机硬约束句]（场景切换型必写）
镜头始终保持在大道正上方，保持相同飞行高度，不升高不降低，不改变视角。

[一致性 / 物理限制]
无瞬移、无肢体变形、无方向错乱。
```

**要点**
- **显式声明 `一镜到底` / `单镜头`**，并说明相机怎么连续运动（后拉 / 跟随 / 摇镜 / 环绕 / 俯冲）。
- 需要锁死视角时用**连续否定句**：`始终保持…，不升高不降低，不改变视角`。
- **事件按发生顺序写**，不要切成 `0-3秒` 时间轴（那是 T3）。
- 场景切换型（一镜到底场景切换）用"镜头穿越…逐渐显现…，连接到{素材}的{新场景}"做**无缝过渡**，而不是切镜。
- 收尾约束句写全片的物理与排斥项（`真实物理运动，无人物主体，无镜头切换，无突然变焦，连续流畅运动`）。

## 五、T5 视频驱动

**适用情况**：**手上有一段参考视频**，要把它的运镜 / 动作 / 节奏迁移到新主体与新场景上。范例 视频驱动。

```
严格参考: <参考视频文件名>的<白模运镜 / 打斗动作 / 镜头运动 等>
场景变为图片N，<原主体>变为图片M，其他角色分配给<角色描述>图片K
```

**要点**
- **第一句必须写 `严格参考:`** 并点明要迁移的维度（运镜 / 动作 / 镜头运动），这是该模板的触发词。
- **映射用"变为 / 分配给"**：场景、主体、配角逐项给出替代素材编号（范例：`场景变为图片74，蓝色模型人物变为图片48，其他角色分配给四个坏人1图片28`）。
- 参考视频承载**运动与节奏**，图片承载**外观与身份**；不要用文字重复描述视频里已有的动作细节。
- 可以叠加 T2 的时间轴对位，但要保持第一句 `严格参考:` 不变。

## 六、共用配件（5 个模板都能挂）

### 6.1 素材说明（范例几乎都有）

按**角色**声明每份素材管什么，一句话一条；**不要**只说"参考图片N"：

| 角色 | 例子（来自范例） |
|---|---|
| 首帧 / 构图 | `图片56为首帧参考`；`图片 56_构图` 是**去掉前景遮挡的构图版** |
| 场景 | `图片32` 香港咖啡店街角（**跨范例复用**：单一 02/03/04 与连续 04 都指同一张） |
| 人物三视图 | `图片49作服装参考`、`图片47` 设定、`图片48`（正/背/近景） |
| 正脸五官 | `五官参考 Stati..2.png`（纯背景正脸照，只管脸与发型） |
| 道具 | `手中道具参考:图片75 保留蓝白渐变坠饰与磨损金属质感`（道具四视图） |
| 配角 / 动物 | `Stati..8`（配角）、`图片106`（小狗三视图）、`图片2`（跳蛛三视图） |
| 变形 / 替换对象 | `图片18`（仙人掌）、`图片20`（鸵鸟）、`图片21`（萨克斯手）、`图片101/103` |
| 多角色分配 | `其他角色分配给四个坏人1图片28`（一张图里四个角色，逐个分配） |
| 参考视频 | `飞书202...7.mp4`（只用它的运镜与动作） |

长文件名在范例里被**缩写**（`Stati..2.png`、`飞书202...7.mp4`）只是书写习惯；DSH 提交时一律换成顺序编号 `图片N`（见第七节）。

### 6.2 光影三层（范例 01/02/04 都显式标注）

```
光影: <光源层>，<光行为层>，<色调层>
```

- **光源层**：光从哪来（阴天冷漫射光、高楼缝隙斜射暖阳、道具冷蓝自发光）
- **光行为层**：光在画面里怎么起作用（玻璃反射遮挡面部、街面暖色反光、蓝光沿金属边缘流动）
- **色调层**：整体调子（低饱和城市灰米底调、克制暖阳高光、牛仔蓝与冷蓝道具光对比）

### 6.3 音效行

独立一行 `音效:`（或范例 06 的尖括号 `<…>` 行）。写具体声源：`玻璃门急促推开声、紧张脚步、呼吸由急转缓、金属环轻碰声`。
无音频时按 DSH 默认追加 `不生成音乐，仅生成音效。`

### 6.4 禁止项

范例统一收尾：`禁止：任何文字、字幕、LOGO或水印`。只写当前确实要排除的项。

### 6.5 画质与稳定性

- 画质规格写在整体设定（T2）或开头（T1/T3/T4）：`写实电影质感`、`35mm胶片颗粒`、`手持纪实摄影`、`85mm长焦浅景深`、`28mm广角手持`。
- **稳定性/一致性限制**单独一段，写全片恒定项与禁用项（`同一面孔发型服装`、`无瞬移`、`无肢体变形`、`空间方向不跳变`、`不要慢动作`）。

## 七、素材编号与绑定（所有模板共用）

### 双栏口径（必须转换）

| | 编号含义 | 形态 |
|---|---|---|
| **官方原形**（仅用于理解范例） | **素材库内的文件名编号**，可跳号、可带 `(2)`，**跨范例复用同一编号指同一素材** | `图片32` `图片49` `图片75` `图片28(2)` |
| **DSH 落地形**（提交必须用） | 该段 `images` 数组的**传入顺序**，按 **图片 → 视频 → 音频** 计数 | `图片1` `图片2` … |

### 转换三步（提交前逐段执行）

1. **列清单**：把该段真正引用到的素材按传入顺序排好，得到 `图片1..N`。
2. **换编号**：官方原形编号整换为顺序号；中文数字（`图片一`）也换成 `图片1`。
3. **去版本括号**：`图片28(2)` 这类变体要么作为**独立素材单独传入**并占用自己的顺序号，要么不引用。
   **不得**残留原始文件名（`图片 56_构图`、`Stati..2.png`、`飞书202...7.mp4`）——
   `project_pipeline` 会把内部素材文件名判为泄漏并拒绝。

```text
官方原形（理解用）              DSH 落地形（提交用）
图片56为首帧参考               →  图片1为首帧参考
图片49作服装参考               →  图片2作服装参考
五官参考 Stati..2.png          →  五官参考图片3
手中道具参考:图片75            →  手中道具参考图片4
场景变为图片74，主体变为图片48  →  场景变为图片1，主体变为图片2
```

### 标签纪律

- 只用中文裸标签 `图片N` / `视频N` / `音频N`，内联在它描述的对象后面；**同一素材全片沿用同一编号**。
- 每份素材分配**单一职责**（只管脸 / 只管服装 / 只管场景 / 只管道具），并说明什么**不要**从它迁移（范例：`仅参考指定主体，不迁移原图背景和无关人物`）。
- 每段 prompt **整体**至少含一个 `图片N`（`set_prompts` 会拒写没有绑定的段）；这是"每段一个"，不是"每镜一个"。

### 画布直调时的绑定形态（硬规则）

把提示词**直接写进即梦画布节点**（`dreamina-canvas node create|edit image|video ... --prompt`，即不经 `prompt_batch` / `generate_video` 的适配器）时：

- **裸标签 `图片N` / `视频N` 在画布正文里只是普通文本，不会建立引用。** 读回节点时 `generation.promptParts` 只有一个 `kind: "text"` 段，画布 UI 里显示的就是死文字"图片1"——素材虽然挂在节点上，正文却没有任何绑定。**2026-10-14 真实事故**：按本模板写成裸标签落进画布后，用户看到的是文字的"图片1 / 视频1"。
- 画布自己的绑定形态是 **`{{res:<小写规范 UUID>}}`**（或 `{{node:<nodeId>}}`）；保存后 `promptParts` 会出现对应的 `kind: "reference"` 条目。第七节的 `图片N` 编号是**提交文本层**的写法，由 `generate_video` 适配器转换成绑定形态；**绕开适配器就必须自己写绑定形态**。
- 模板结构与绑定形态**并存**：首句仍是 `严格参考:`，把素材位置写成 `严格参考:{{res:<视频 UUID>}}的镜头运动…`；**同一素材只插一次占位符**，其余位置用"该参考视频 / 该图片"指代，避免同一素材被重复插入。
- **保存后必须自检**：读回节点，确认 `generation.promptParts` 里 `kind: "reference"` 的条目数与素材数一致，且 `generation.references[]` 份数等于素材数；只有 `text` 段就是没绑定，必须重写。
- 画布槽位顺序**按正文中首次出现的位置**决定（`--ref` 的传入顺序不生效）。T5 首句是 `严格参考:<视频>`，因此视频会排在图片之前——这是预期行为，不要为此改动 T5 首句。

## 八、允许与禁止的写法

### ✅ 合法（官方范例都在用）

- `镜头N` 编号式分段（`镜头1`、`镜头2:`、`镜头1-2`）
- **时间码 / 秒数区间标题**：`0-1.5秒:`、`0-3秒:`、`[00.0-03.0秒|场景名]`、`[00:00-00:05] 镜头1：`
- **方括号区块头**：`[素材说明]`、`[整体设定]`、`[时间轴]`、`[稳定性限制]`、`【素材说明】`
- 段落内的 `CUT_02 硬切至…` 内部切点声明
- 段级质感句（放最后）、光影三层、音效行、禁止项

### ❌ 禁止

| 禁止 | 为什么 / 替代 |
|---|---|
| 管道符拼接的分镜标题：`0.0-4.0 秒｜第一段｜图片2` | 代码层会拒绝；改用 `0.0-4.0 秒，第一段，图片2。` 或 `[00.0-04.0秒\|第一段]` |
| `@Image1`、`@img1`、`@图片1`、`参考图片1` | 会被 `normalizeReferenceLabels` 改写，但不得主动写；用裸标签 `图片1` |
| 内部素材文件名 / 缩写文件名留在正文（`Stati..2.png`、`飞书202...7.mp4`） | 会被判为泄漏并拒绝；换成 `图片N` |
| 模型名、分辨率、帧率、码率、`15 seconds, 24fps, no subtitles` | 走结构化参数（时长/画质规格可写进 `[整体设定]` 的自然语句，如 `12秒，16:9，720p`） |
| 段级负面清单（一长串"不要…"） | 排斥项内联在需要它的那一句；只有 `[稳定性限制]` 这类集中约束段是范例认可的 |
| 同一份提示词混用两种分段体系 | 同一层只用一种：`镜头N` 或 时间码/秒数区间 |

## 九、交付前自检

- **选了哪个模板？** 与"有分镜 / 单镜头 / 有参考视频 / 要不要卡点"对得上吗？
- **同一层只用一种分段手段**吗？（没有在同一批镜头上既写 `镜头N` 又写 `[00.0-03.0秒|…]`）
- `[整体设定]` 是否写了时长、比例、分辨率、质感？是否声明了 `无对白 / 无字幕 / 无BGM`（如适用）？
- 每段的音效是否成行？`[稳定性限制]` 是否覆盖了恒定项与禁用项？
- 素材说明是否**逐份声明了角色**（脸 / 服装 / 场景 / 道具 / 变形对象）？是否写了"不迁移什么"？
- `图片N` 是否已按**传入顺序**重编号？同一素材是否同号？是否残留原始文件名或 `(2)`？
- 光影是否写了三层（光源 / 光行为 / 色调）？
- 禁止项是否只保留了当前确实要排除的？
- 时长 / 比例 / 分辨率 / 模型是否留在工具参数里（或写进 `[整体设定]` 的自然语句）？
- 用户未指定音频时，是否已追加 `不生成音乐，仅生成音效。`？
- 若这份提示词要**直接写进画布节点**（不经 `generate_video`）：素材位置是否已写成 `{{res:<小写UUID>}}` / `{{node:<nodeId>}}`，而不是裸标签 `图片N`？保存后读回节点，`generation.promptParts` 里是否出现了与素材数一致的 `kind:"reference"` 条目？槽位顺序是否与正文首现顺序一致？
