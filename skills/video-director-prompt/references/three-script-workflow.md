# 三层脚本工作流（2026-11-08 用户定）

一条片子的脚本要分三层写，每层解决不同问题、给不同人看。**不要跳层，也不要混写。**

```
① 导演脚本（小说体）      讲清楚"这场戏是什么样"        → 给人看，定调
        ↓
② 执行脚本（九列分镜表）  讲清楚"怎么拍"                → 给剧组/给自己拆镜
        ↓
③ 即梦提示词脚本（11 区块）讲清楚"给模型什么指令"        → 给 AI 生成
```

## 第一层：导演脚本

**形态：一整篇可读的故事，不拆段。**

用户 2026-11-07 原话：「把之前给你的脚本当作一个故事大纲……导演脚本……可以当作一个小说/小故事来写，以画面感的描述为主」「把整个故事一起写了，不要拆成很多段」。

**必须**：
- **小说体、画面感**：写空间、光、天气、人物的动作与表情、声音、气味；让读者能在脑子里"看见"
- **整篇连续写完**：不要在段落之间插入镜头编号、时间码、表格
- **情绪与节奏**：写清这一段是快是慢、是热闹还是安静、观众该有什么感受
- **人物状态**：谁在哪、在做什么、为什么这么做

**不要**：
- 不要写景别、焦段、机位高度（那是执行脚本的事）
- 不要写"画面 1""镜头 2"这类编号
- 不要写成提纲或要点列表
- 不要拆成一堆小段

**示例句式**：
> 午后的光从高窗斜进来，把木地板照出一层暖黄。台下是密密麻麻的后脑勺，掌声从四面八方涌上来又慢慢退下去。台上两个人并排站着，高的那个把折扇往掌心一拍，扇骨发出清脆的一声，矮的那个被这声响震得缩了缩脖子，随即咧嘴笑起来。

## 第二层：执行脚本（九列分镜表）

**形态：九列分镜表**，逐镜拆解导演脚本。

| 列 | 内容 |
|---|---|
| 镜号 | 1、2、3…（全片连续） |
| 时长 | 秒数，精确到 0.1s |
| 摄影角度 | 平视 / 仰 / 俯 / 过肩 / 航拍 |
| 景别 | 大特写 / 特写 / 近景 / 中景 / 中全景 / 全景 / 大全景 |
| 画面内容 | 这一镜发生什么（动作、台词、表情） |
| 场景 | 场景卡编号或地点名 |
| 声音 | 台词、环境声、音效 |
| 备注（运镜） | 推拉摇移跟升降、方向与速度 |
| 叙事目的 | 这一镜为什么存在（交代/铺垫/转折/收束） |

**时长配置**（先定段时长，再倒推镜数）：
- 建立镜 2.0–2.5s ／ 反应镜 1.5–2.0s ／ 特写 1.0–1.5s ／ 落点 0.8–1.5s
- 平均 1.5–2.5 秒/镜；先算台词秒数，再加动作镜与转场镜

**镜头设计三原则**（详见 `ai-video-shooting-rules.md` 第九、十、十一节）：
- 视线匹配：角色看什么，先给反应近景，再给被看对象（景别按信息选）
- 动作拆解：动作先局部特写，再给结果或关系
- 场景切换**默认**用特写开场（非硬性）

**输出**：markdown 表格或 xlsx；同一批镜头不要在表里混用"镜号"与"时间码"两种分段方式。

## 第三层：即梦提示词脚本

**形态：11 个区块**（结构见 `jimeng-standard-template.md` 与 `ai-video-shooting-rules.md` 第八节）：

```
【风格】【布光锁定】【参考】【设定】【特殊要求】【导演】
【故事背景】【画面内容】【镜头】【一致性】【限定】
```

硬要求：
- 【画面内容】与【镜头】**分开，逐镜 `镜N` 编号一一对应**，镜数必须相等
- 【参考】里素材必须绑定 `{{node:...}}` / `{{res:...}}`
- 【限定】第一条必须是"禁止加背景音乐"
- 每段 < 4000 字符（2.0fastvip 限制）

## 三层怎么衔接

| 层 | 谁看 | 变更影响 |
|---|---|---|
| 导演脚本 | 客户 / 导演 / 自己 | 改故事 → 下游全改 |
| 执行脚本 | 拍摄与分镜 | 改镜数/时长 → 提示词全改 |
| 即梦提示词 | AI 模型 | 只改措辞与引用，不改结构 |

**改任何一层，下游必须同步重出一遍**，不能只改中间层。
