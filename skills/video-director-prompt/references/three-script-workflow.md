# 三层脚本工作流（2026-11-08 用户定）

一条片子的脚本要分三层写，每层解决不同问题、给不同人看。**不要跳层，也不要混写。**

```
① 导演脚本（小说体）      讲清楚"这场戏是什么样"        → 给人看，定调
        ↓
② 执行脚本（九列分镜表）  讲清楚"怎么拍"                → 给剧组/给自己拆镜
        ↓
③ 即梦提示词脚本（11 区块）讲清楚"给模型什么指令"        → 给 AI 生成
```

## 第一层：导演脚本

**形态：一整篇可读的故事，不拆段。**

用户 2026-11-07 原话：「把之前给你的脚本当作一个故事大纲……导演脚本……可以当作一个小说/小故事来写，以画面感的描述为主」「把整个故事一起写了，不要拆成很多段」。

**必须**：
- **小说体、画面感**：写空间、光、天气、人物的动作与表情、声音、气味；让读者能在脑子里"看见"
- **整篇连续写完**：不要在段落之间插入镜头编号、时间码、表格
- **情绪与节奏**：写清这一段是快是慢、是热闹还是安静、观众该有什么感受
- **人物状态**：谁在哪、在做什么、为什么这么做

**不要**：
- 不要写景别、焦段、机位高度（那是执行脚本的事）
- 不要写"画面 1""镜头 2"这类编号
- 不要写成提纲或要点列表
- 不要拆成一堆小段

**示例句式**：
> 午后的光从高窗斜进来，把木地板照出一层暖黄。台下是密密麻麻的后脑勺，掌声从四面八方涌上来又慢慢退下去。台上两个人并排站着，高的那个把折扇往掌心一拍，扇骨发出清脆的一声，矮的那个被这声响震得缩了缩脖子，随即咧嘴笑起来。

## 第二层：执行脚本（九列分镜表）

**形态：九列分镜表**，逐镜拆解导演脚本。

| 列 | 内容 |
|---|---|
| 镜号 | 1、2、3…（全片连续） |
| 时长 | 秒数，精确到 0.1s |
| 摄影角度 | 平视 / 仰 / 俯 / 过肩 / 航拍 |
| 景别 | 大特写 / 特写 / 近景 / 中景 / 中全景 / 全景 / 大全景 |
| 画面内容 | 这一镜发生什么（动作、台词、表情） |
| 场景 | 场景卡编号或地点名 |
| 声音 | 台词、环境声、音效 |
| 备注（运镜） | 推拉摇移跟升降、方向与速度 |
| 叙事目的 | 这一镜为什么存在（交代/铺垫/转折/收束） |

**时长配置**（先定段时长，再倒推镜数）：
- 建立镜 2.0–2.5s ／ 反应镜 1.5–2.0s ／ 特写 1.0–1.5s ／ 落点 0.8–1.5s
- 平均 1.5–2.5 秒/镜；先算台词秒数，再加动作镜与转场镜

**镜头设计三原则**（详见 `ai-video-shooting-rules.md` 第九、十、十一节）：
- 视线匹配：角色看什么，先给反应近景，再给被看对象（景别按信息选）
- 动作拆解：动作先局部特写，再给结果或关系
- 场景切换**默认**用特写开场（非硬性）

**输出**：markdown 表格或 xlsx；同一批镜头不要在表里混用"镜号"与"时间码"两种分段方式；表外必须给出任务分组表。

### 具象写法 · 拍什么／拍哪里（2026-11-10 定，执行脚本的第一职责）

九列是骨架；执行脚本真正要交付的是**「画面里究竟拍什么、拍哪里」**——因为写它的 Agent **能真实打开场景卡看图**，这是纯文字模型做不到的。

- **依据三样**：导演脚本的诗意描述 ＋ **场景卡原图（必须逐张打开看）** ＋ 用户定的镜头规则。景别、机位、运镜由 Agent 读过导演脚本后自己判断。
- **每镜 2 行**：
  1. `拍什么·拍哪里：` 画面里有什么（主体／前景中景背景／人物位置／视线／光落在什么材质）＋ **取场景卡的哪一块**（哪部分进画、什么不要进画；卡与剧本时段或角度不符时，写清"空间照用、光或机位重打"）。
  2. `景别·机位·运镜·声音：` 景别｜机位高度·角度·焦段｜运镜｜声音／时长。**技术参数全保留**。
- **细节 2–4 句**：只留能被拍到的实体（"雨中古巷纵深、青石板反光、屋檐滴水成帘"）。细节本身可以是给特写的理由（"睫毛上的粉、眉心的红"→ 值得一个特写），是否真给镜头由 Agent 判断。
- **全景／特写的切换点看相邻镜**：同一段描写天然既是"全景切特写"也可能是"特写切全景"，按整篇章的景别节奏取舍，不必每镜写死。
- **先核对卡面再写**：卡的时段、视角、主体常与卡名不符（例：日落卡不能当日出用；马路视角的楼阁卡没有江面金光；全身双偶的舞台卡要特写就写"推近"）。核对结果写进"拍哪里"，不照抄卡名。
- **缺卡／缺道具卡**：不在脚本里硬写、不自己编——**全片做完一次性汇总**给用户补卡；缺卡镜先给替代写法（相邻元素替代或切概念特写）。
- **人物**：角色卡与场景卡**配合生成**（不是后期合成）；**概念元素**（窗灯、烟火等）可让画面直接生成、可切特写或省略；**不考虑后期**。

### 生成任务分组（2026-11-10 定，硬规则：在做执行脚本时完成）

执行脚本这一层就要把镜头圈成**生成任务**（＝后面喂给即梦的一个节点、一段提示词），分组在本层定死；**提示词层只按组执行，不得重新分组**。

- 每任务 **4–10 秒**、含 **2–4 镜**；超过 10 秒的连续长镜头按长镜头规则单独处理（可 1 镜成任务）
- 每任务 **≥3 个景别**（形成特写 → 中景 → 全景的节奏）
- **有人物的任务不跨场景**；必须换场时最多 1 次，且用人物局部特写做桥
- 每任务参考素材 **≤9 张图**
- 单句 **2 秒以内**的插入镜允许 **1 镜成任务**（不适用 3 景别）
- 每个任务标注类型：**连续任务**（同一空间内时间轴推进）／**快切组**（独立短镜、剪辑合成）
- 输出时在九列之外加"任务"维度（任务号 + 时长 + 镜次范围 + 素材）；某任务写不下就回改本层重新分组，再把下游提示词整组重出

**为什么放在这一层**：任务的边界由时长、景别、场景、人物、素材决定，这些字段只在本层；放到提示词层再分组，会出现两层镜号映射错位、返工成本翻倍。

## 第三层：即梦提示词脚本

**形态：11 个区块**（结构见 `jimeng-standard-template.md` 与 `ai-video-shooting-rules.md` 第八节）：

```
【风格】【布光锁定】【参考】【设定】【特殊要求】【导演】
【故事背景】【画面内容】【镜头】【一致性】【限定】
```

硬要求：
- 【画面内容】与【镜头】**分开，逐镜 `镜N` 编号一一对应**，镜数必须相等
- 【参考】里素材必须绑定 `{{node:...}}` / `{{res:...}}`
- 【限定】第一条必须是"禁止加背景音乐"
- 每段 < 4000 字符（2.0fastvip 限制）

## 分层分工（2026-11-10 定）

| 层 | 谁做 |
|---|---|
| ① 导演脚本 | **Gemini**：Agent 给故事大纲＋参考图，Gemini 写正文；Agent 只校准事实与结构 |
| ② 执行脚本（含任务分组） | **Agent 自己做**，不交给 Gemini |
| ③ 即梦提示词脚本 | **Agent 自己做**：常量块、素材绑定、逐镜画面与镜头行（取自执行脚本的改写） |

- **Gemini 只负责导演脚本和布光／风格锁定**。执行脚本、提示词脚本由 Agent 完成，不调用 `creative_writer`。
- 提示词层的"创意正文"不再外包：画面内容与镜头行直接由执行脚本改写成提示词语言，保证两层镜号一一对应、不被模型改写。
- 调用 Gemini 时 brief 只给「片子基本事实＋图序＋输出要求」；有图必传、Agent 不描述图内容。

## 三层怎么衔接

| 层 | 谁看 | 变更影响 |
|---|---|---|
| 导演脚本 | 客户 / 导演 / 自己 | 改故事 → 下游全改 |
| 执行脚本 | 拍摄与分镜 | 改镜数/时长 → 提示词全改 |
| 即梦提示词 | AI 模型 | 只改措辞与引用，不改结构 |

**改任何一层，下游必须同步重出一遍**，不能只改中间层。
